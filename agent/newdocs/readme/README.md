## 二、 规范编写与维护原则

1. **文档驱动开发 (Documentation-Driven Development)**：
   * 架构调整与需求变更遵循“**文档先行 → 页面调整**”的流程，避免代码与文档脱节。
2. **三态透明原则**：
   * 在功能清单中严格区分【已实现（真实数据闭环）】、【演示脚本（Mock预置流）】、【预留（占位未实现）】，不混淆交付边界。
3. **确定性与AI生成边界清晰**：
   * 明确界定算法引擎（确定性运算、不可篡改）与大模型辅助（语言润色、意图识别）的职责划分。
4. **模块解耦与数据穿透**：
   * 严格遵循“公域权威规则（运维管理） vs 私域企业台账（组织资源）”的架构分界，确保所有报告数据均具备直达底层源头的穿透证据链。
