## 一、 系统技术架构与工程分层

### 1.1 总体技术栈与依赖
* **前端工程体系**：Vue 2.6.x + Element UI 2.15.x + Less / Sass
* **图表可视化组件**：ECharts 5.4.x（满足工业级能碳图表渲染规范）
* **离线与导出体系**：`docx 9.x`（Word深度解析生成）+ 纯前端 CSV/XLSX 导出与动态元信息水印
* **架构核心模式**：纯前端数据状态机驱动、受控 AI 与规则引擎物理隔离机制

### 1.2 页面状态机与双模态 (Dual-Mode) 设计
在复杂工作台（如智慧报告中心）中，采用 `pageMode` 状态机实现两种视角的平滑调度：
* **模态 A：接待总览态 (`pageMode: 'home'`)**：
  * 左栏会话历史树 + 中间智能对话流 + 右侧双页签聚合工作台（任务列表 + 排期规则）；
  * 职责：意图识别、宏观排期计划管理、跨期任务看板展示。
* **模态 B：任务激活沉浸态 (`pageMode: 'active'`)**：
  * 左栏副驾驶辅助 + 中间四阶段串行向导（Scope → Hydration → Verification → Filing）；
  * 职责：全神贯注完成单份公文的合规编排，硬闸门串联各阶段。

## 二、 核心中枢引擎技术实现

### 2.1 因子匹配引擎与四级调度算法 (`factorMatchingService`)
* **核心调度算法**：
  ```
  输入指标项(Name, Unit) 
    ├── 1. 检索企业因子库：匹配企业实测因子 (P-1，凭证有效且在保)
    ├── 2. 检索历史纠偏库：命中企业记忆 (P0，cfp_factor_mapping_memory)
    ├── 3. 匹配规则引擎库：根据行业与应用场景映射规则表
    └── 4. 兜底官方缺省库：引用生态环境部权威缺省公因数
  ```
* **版本防漂移机制 (`templateLock`)**：
  任务实例在创建时刻，将当前生效的标准文号、模板版本、因子代码深度克隆并持久化至任务实例中；即使后续平台标准库升级，历史任务依然严格按照创建时锁定的法律依据执行。

### 2.2 数据源头穿透管道技术设计 (Trace Pipeline)
* **业务目标**：报告任意关键指标，点击即穿透至底层通用物理表计与发票凭据。
* **技术实现**：
  1. 表格单元格统一挂载 `:class="{ 'rwb-val-penetrate': isPenetratable(...) }"`；
  2. 点击触发 `onTableCellClick`，根据行列信息调用 `buildPenetrationData`；
  3. 结构化组装三层数据：
     * **呈现层**：报告指标名称、当前填报值、锁定的法定口径；
     * **规则层**：折算公式（如 `E = AD × EF`）、选定因子代码及法规文号；
     * **源头层**：物理表计编号（如 EM-0104）、原始读数、SCADA采集时间戳、发票凭单号、防篡改验签状态。
  4. 唤起统一右侧滑动抽屉 (`penetrateDrawer`) 进行结构化渲染。

### 2.3 受控 AI 改写护栏机制 (AI Guard)
* **物理隔离**：AI 改写仅接收 `ch.content.narrative` 纯文本，不接触表格核心数值字段；
* **数值校验拦截**：改写完成后，系统通过正则表达式提取新旧文本中的全部数字数组，比对新旧数值集是否严格一致：
  * 若数值发生变化（如 AI 擅自将 2140 改为 2100）：触发 `guard.level = 'block'`，物理禁用“接受”按钮，提示“该改动不可接受：报告数据须与规则引擎换算结果一致”；
  * 仅当数值完全未变时，允许采纳并写入正文。

### 2.4 SHA-256 内容指纹防篡改算法
* 归档时，遍历整篇报告的所有元数据、章节段落、附表单元格数据，序列化为规范化 JSON 字符串；
* 调用纯前端密码学算法计算其标准的 64 位 SHA-256 哈希值；
* 生成防伪指纹存证单，并在所有导出的 PDF、Word 文件页脚嵌入该哈希水印。

## 三、 数据模型与持久化规范

### 3.1 本地存储命名空间隔离 (Local Storage Namespaces)
为了保证各场景数据不冲突，在前端原型中规范了如下 LocalStorage 键名前缀：
* `cfp_*`：产品碳足迹业务数据池；
* `pef_*`：产品环境足迹业务数据池；
* `org_carbon_reports_v2`：组织碳核算归档数据池（供智慧报告只读消费）；
* `rs_reports_v1` / `rs_calendar_v1`：智慧报告任务实例与排期计划库；
* `cfp_formula_library`：核算公式库本地配置缓存。

### 3.2 生产环境 API 接口对接对齐表（规范指引）
| 前端数据实体 | 对应生产微服务 | 接口协议与路由 | 数据格式 |
|:---|:---|:---|:---|
| 报送排期计划 | 规则调度服务 | GET/POST `/api/v1/report/calendar` | JSON Schema |
| 报送任务实例 | 任务流程引擎 | GET/PUT `/api/v1/report/tasks/{id}` | Task Entity |
| 实时采集数据 | 统一数据底座 | GET `/api/v1/telemetry/timeseries` | REST/WebSocket |
| 官方凭证回执 | 档案与存证服务 | POST `/api/v1/archive/receipt` | Multipart Form |
