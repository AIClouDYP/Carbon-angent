# 智慧报告五阶段生命周期与公共支撑联系

> 隶属模块：report-submission | 定位：报告生成智能体五阶段生命周期与基础支撑功能的引用关系总览
> 用途：细化设计 / 汇报讲解 / 新成员理解全局的入门图
> 关联文档：[报送任务编排详情](Orchestration.md)（编排界面四阶段条与各阶段功能点明细）· [基础支撑功能要求](Orchestration.md)（§5，细化设计输入）· [智能体中心·资源库群](../agent-center/agent-center.md)（支撑方管理侧）

## 0. 阶段口径说明（生命周期五阶段 vs 编排界面四阶段条）

报告智能体生命周期划分为**五个阶段**；其中 Stage 0（任务创建与意图实例化）发生在**工作台**（新建报送计划 / 临时报告 / 日历期次派生），用户进入编排详情时 Stage 0 已完成——因此**编排界面内的阶段推进条为四段**（对应 Stage 1~4），生命周期叙事采用五段。

| 生命周期 | 编排界面 | 发生位置 |
|---|---|---|
| Stage 0 任务创建与意图实例化 | —（工作台动作） | 工作台：新建报送计划 / 临时报告 / 日历期次派生 |
| Stage 1 适用性裁定确认与基准锁定 | 阶段一 · 模板匹配与主体核对 | 编排详情 |
| Stage 2 数据补全与质量对齐 | 阶段二 · 数据采集与补录 | 编排详情 |
| Stage 3 受控生成与双重校验 | 阶段三 · 生成与校验 | 编排详情 |
| Stage 4 三级签发与提报归档 | 阶段四 · 确认归档 | 编排详情 |

> 时点说明：templateLock 与场景路由在 **Stage 0 末尾即生成**（创建即锁定——防口径漂移、期次自动派生的前提）；Stage 1 在编排中做的是**裁定确认**（复核场景裁定、核对主体、确认编制依据、合规预警上浮），而非重新裁定。

## 1. 数据流主线（谁产出、谁消费）

```
平台模板库 ──类型/预填/场景条件──→ 【Stage 0】任务创建与意图实例化（工作台）
企业档案 ──主体绑定──↗
报送日历 ──期次派生──↗
        │ 任务上下文（任务实例 + templateLock/sceneRule 创建即锁定）
        ▼
政策标准库 ──编制依据/现行性核验──→ 【Stage 1】裁定确认与基准锁定（编排阶段一）
平台模板库 ──结构预览/清单骨架──↗
企业档案 ──概况核对──↗
        │ 锁定的指标清单骨架（Metric Skeleton）
        ▼
离线导入服务 ──解析回填──────→ 【Stage 2】数据补全与质量对齐（编排阶段二）
        │ 审计级就绪数据集（Hydrated Dataset）
        ▼
因子库/匹配服务 ──因子取值+溯源──→ 【Stage 3】受控生成与双重校验（编排阶段三）
公式库 / 政策标准库 ──公式/口径/条文──↗
        │ 校验通过的完整初稿包（Verified Draft）
        ▼
导出服务 / 签发引擎 ──渲染+指纹──→ 【Stage 4】三级签发与提报归档（编排阶段四）
碳报告中心 ←──归档登记/编号回写/提报状态──┘
```

## 2. 各阶段明细

### Stage 0 · 任务创建与意图实例化（工作台）

**作用**：用户/调度中心发起——选择报送类型、统计期次、绑定企业主体，完成初始任务实例创建；创建即锁定模板版本与场景路由（templateLock / sceneRule）。

| 公共支撑 | 取用内容 |
|---|---|
| 平台模板库 | 报告类型目录、三级预填（模板配置→AI→空白）、场景适配条件（创建必选）、版本 |
| 企业档案 | 企业主体绑定（填报领域/行业等分流属性） |
| 报送日历（自建能力） | 周期任务的期次自动派生、提报窗口 |

**回写**：任务实例（rs_reports_v1）+ 创建时快照（templateLock 完整引用对象 / sceneRule）→ Stage 1 复核基准、Stage 2 采集清单范围由此确定。

### Stage 1 · 适用性裁定确认与基准锁定（编排阶段一）

**作用**：复核创建时的场景裁定与模板锁定（不为改版重裁），核对主体信息（用能单位概况），确认编制依据；合规风险上浮（依据废止/标准更新/模板改版漂移）。

| 公共支撑 | 取用内容 |
|---|---|
| 平台模板库 | 模板章节结构预览、锁定版本展示 |
| 政策标准库 | 编制依据规则集（四类参数/执行映射/条款引用，经 standardCode 引用）；依据现行性核验（废止/更新预警） |
| 企业档案 | 用能单位概况字段带出核对 |

**回写**：基准确认（主体/依据/场景三确认）→ 决定 Stage 2 采集清单范围与免填/条件判定。

### Stage 2 · 数据补全与质量对齐（编排阶段二）

**作用**：数据补全与质量对齐（缺项消番工作台）——数据池自动引用之外的四通道补录（表格导入 / 在线填报 / AI 对话引导 / 缺项模板批量下载），填报一线防呆（±50% 波动预警），完整性闸门清零后放行。

| 公共支撑 | 取用内容 |
|---|---|
| 离线导入服务 | CSV 解析、字段映射建议与置信度、章节/批量模板下载 |
| 平台模板库 | 采集清单骨架（按报表章节分组）、免填/条件判定依据 |
| 企业档案 | 自动豁免判定（场景免填、数据中心等条件性表格） |

**回写**：审计级就绪数据集（Hydrated Dataset）、采集完成度与缺项清单（驱动左侧对话引导与锚点定位）、回填记录（入修订留痕）。

### Stage 3 · 受控生成与双重校验（编排阶段三）

**作用**：双轨分工——规则引擎确定性换算与勾稽校验（AI 不参与算数）+ Agent 受控合规文本与异动说明生成；校验总览为客观计数（通过 / 总数 + 待处置），异常处置清零后产出。

| 公共支撑 | 取用内容 |
|---|---|
| 排放因子库/匹配服务 | 因子取值（matchFactor：场景路由/历史映射记忆/置信度/命中记录）、单位归一 |
| 公式库 | 换算公式（appliedStandard 关联，公式可执行可追溯） |
| 政策标准库 | 口径参数执行、条文引用（规范合规比对与合规声明） |
| 导出服务 | 整篇预览导出（PDF 等） |

**回写**：换算依据（因子溯源六要素）、校验结果集（9 类规则）、校验客观计数（必须项未通过即阻断）、异常处置记录 → 校验通过的完整初稿包（Verified Draft）。

### Stage 4 · 三级签发与提报归档（编排阶段四）

**作用**：闭环管理——内控三级审核（填报人自查→部门负责人→碳管理师复核）、内容指纹签章、渲染导出、归档登记与监管回执/文号回写。注意：签字归档 ≠ 提交成功，提报状态由人工登记推进。

| 公共支撑 | 取用内容 |
|---|---|
| 导出服务 | 5 格式导出，统一嵌入元信息水印（来源智能体/任务/期次/指纹） |
| 签发引擎 | 内容指纹生成 + 完整性随时校验（检出签发后任何改动） |
| 碳报告中心 | 归档登记（部门+期次命名）、报告编号回写、查看/下载、提报/受理原型实现度登记 |

**回写**：归档文件与报告编号 → 任务状态（已归档·待提报）、工作台任务状态同步（提报/受理登记回写政府回执凭证）。

## 4. 三条贯穿性原则

1. **引用与本体分离，创建即锁定**：模板只持引用声明（standardCode / formulaStandard / factorVersion），规则本体在标准库/公式库/因子库；templateLock 在 Stage 0 末尾生成，政策升版一处生效、在途任务不受改版影响。
2. **全程可追溯**：换算有因子溯源六要素，人工动作入修订留痕，签发有内容指纹，归档有报告编号——从报告数字到原始采集四级可回溯。
3. **双轨分工**：规则引擎负责确定性换算与勾稽校验（可审计），Agent 负责受控合规文本生成、缺项引导与对话交互——数字合规可信，文本高效可控。
