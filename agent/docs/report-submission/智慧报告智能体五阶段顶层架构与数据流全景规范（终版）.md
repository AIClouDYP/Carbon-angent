# **智慧报告智能体全生命周期工程与产品规格说明书（PRD 终版）**

**系统标识**：enterprise-report-agent / report-submission

**定位**：面向工业企业能碳管理、法定节能与碳排双控申报的通用智能体中台规范

**文档版本**：V5.2-RELEASE（全景整合版）

## **第一章 顶层产品哲学与通用架构体系**

### **1.1 核心设计哲学**

1. **确定性边界原则（Determinism Boundary Principle）**：  
   **“凡确定性任务优先自动化，凡存在业务裁决的任务默认交给用户。”**

   &nbsp;系统拒绝为了 KPI 进行不安全的自动化。数据检索、单元格寻址、折标换算与守恒核验由系统 100% 确定性执行；口径冲突、异动解释与免责声明等 20% 关键责任保留给用户。  
2. **通用中台定位（Metadata-Driven）**：  
   系统不为特定报告（如《重点用能单位报告》）硬编码业务逻辑。平台底层标准库解析政策规范与模板 Schema，通用驱动前台所有报表的任务创建、数据补水、校验与存证\[cite: 1, 3\]。

### **1.2 五大核心领域对象驱动模型（DDD）**

业务生命周期由五个不可变的核心领域实体串联推进，上一阶段产物作为下一阶段的强契约输入：

### **1.3 智能体认知自主性梯度**

智能体在不同阶段承担递进的认知职责：

* **阶段一**：理解意图（识别主体、匹配周期）  
* **阶段二**：理解法规（分流场景、裁决豁免、锁定基准）  
* **阶段三**：理解数据（多源对齐、守恒检验、差异归因）  
* **阶段四**：理解报告（确定性换算、受控文本生成、表间勾稽）  
* **阶段五**：理解流程（内控权责签署、防篡改存证、政企提报闭环）

## **第三章 阶段一（Task Setup）与阶段二（Scope Resolution）实施细节**

### **3.1 阶段一前置输入对接**

任务由两类入口触发，进入编排后上下文已固定，主界面不再重复询问：

* **周期性计划**：通过报送日历按预设期次（周、月、年）自动调度生成；  
* **临时报告**：用户通过弹窗手动指定报告类型、时间维度（周 / 月 / 年 / 自定义）与期间快速创建，非周期、不入排期。

### **3.2 阶段二 Scope 落地实施规范**

1. **查验载体按内容形态分流**：  
   * **编制依据明细（文档型文本）** $\\rightarrow$ **右侧滑出抽屉（Drawer）**：展示条文原文、成文格式、字体行距与签署规范；  
   * **模板空白骨架（复杂网格宽表）** $\\rightarrow$ **居中宽屏弹窗（Dialog）**：表 1 等 24 列复杂工业大表保留全屏视口与独立横向滚动，彻底杜绝抽屉内横向嵌套滚动。  
2. **纯数据驱动渲染（Single Source of Truth）**：  
   * 正文章节数、适用附表清单（胶囊标签）、豁免表格项均通过循环遍历模板库 variants.sections 与 collectNa 动态渲染，前端不硬编码任何表名与数量；  
   * 阶段一展示的数据与后续阶段二、阶段三消费的底层元数据保持严格同源\[cite: 1, 3\]。  
3. **锁定语义理顺（只读存证，不搞二次锁定）**：  
   * 任务基准已在任务创建时由系统完成快照固化（templateLock）\[cite: 1, 3\]；  
   * 工作台顶部以**只读存证标签**呈现（🔒 任务基准已锁定 · 模板 v1.0），流转按钮维持原有单向推进语义（\[ 确认主体与范围，进入数据采集 ➔ \]）。  
4. **对话流去长文复读**：  
   * 左侧 Agent 仅保留 1\~2 句引导话术，且文字内涉及的报表数量必须由变量动态插值生成（${variants.sections.length} 套适用报表）；  
   * 研判结论（如“所属制造业 · 年耗能超阈值 $\\rightarrow$ 自动启用【工业企业分支】”）上浮至右侧主工作台顶部展示。  
5. **主体概况中的经济与基础能耗指标“收拢于折叠区”**：  
   * 表 1 包含工业总产值、销售收入、综合能源消费量（当量值）等宏观指标，是正文第二节及后续跨表勾稽的引用源；  
   * 阶段二表 1 章节标记为 self 模式，直接继承阶段一字段；因此该组指标**必须默认收拢于「③ 主体概况与顶层指标」折叠手风琴中**，既保证 1080P 一屏信噪比，又杜绝数据链路断裂。  
6. **统计边界依托真实字段呈现**：  
   * 统计边界通过企业档案真实 bndItems 数组以轻量 Tag 渲染；  
   * 行业领域直接展示企业档案中的原始文本，不强行拼接伪造代码前缀。  
7. **保留两大防御与降级入口**：  
   * **兜底场景选择器**：企业档案信息不全导致场景解析未命中时，在右侧填报场景处降级展示手动下拉选择器；  
   * **依据警示条（Warning Banner）**：当且仅当引用标准发生更新或废止预警时，在 ① 卡片顶部触发琥珀色警示条，平时高度为 0 不占位。

## **第四章 阶段三（Data Hydration）运行时架构与数据治理**

### **4.1 阶段二与阶段三的绝对锁定协议**

* **铁律 1（职责单向依赖）**：阶段二负责“立法”（产出指标清单 RequiredMetrics\[\]），阶段三负责“执行”（给坑填数与质检）。阶段三严禁原地篡改报表结构。  
* **铁律 2（基准冻结）**：templateLock 锁定后，在途任务严格按快照版本执行，不受外界政策规则库升版干扰\[cite: 1, 3\]。

### **4.2 二维正交状态机与问题管理模型**

系统解耦为**两维正交状态 \+ 问题集合（issues\[\]）**：

* **就绪维度（resolutionStatus）**：  
  * AUTO\_RESOLVED：数据源唯一权威，自动对齐入库；  
  * PENDING\_CONFIRM：多源候选冲突（跨期、线损、统计边界分歧），需人工裁决；  
  * PENDING\_FILL：资产库未收录，需人工补录或材料解析。  
* **质量维度（qualityStatus）**：  
  * PASS：通过动态守恒、量级范围与波动率校验；  
  * WARNING：非致命预警（如数值波动偏离基准超 $\\pm 20\\%$，放行但在正文提示附说明）\[cite: 1, 3\]；  
  * BLOCKED：阻断级异常（违反物理守恒边界、负数能耗、严重离群），必须纠偏或提供豁免备忘。

## **第五章 阶段四（Generation & Verification）与阶段五（Filing & Archive）闭环**

### **5.1 阶段四：双重校验体系设计**

1. **第一重：机器硬核验（100% 规则引擎确定性执行）**

   * 字段完整性、数值合法性、计量单位归一性；  
   * 跨表全量勾稽自洽（表 1 综合能耗与表 2 平衡表平衡一致）；  
   * 校验客观计数：必须项（阻断项）全部通过方可流转，否则阻断\[cite: 1, 3\]。  
2. **第二重：人工业务校验（人类审阅签字）**

   * 核心生产与能耗指标复核；  
   * 敏感合规文本审阅；  
   * 异动原因核准：对波动超 $\\pm 20\\%$ 的指标原因说明做最终责任定稿\[cite: 1, 3\]。

### **5.2 阶段五：三级签发演进与政企隔离闭环**

* **权限与审批分步演进机制**：  
  * **当前版本（轻量基线）**：单人闭环确认，记录当前操作人并固化 SHA-256 内容指纹；  
  * **未来规划（多级审批）**：数据模型向后兼容 ApprovalNode\[\] 审批链，待企业统一权限中心（RBAC/ABAC）就绪后平滑开启三级工单协同。  
* **政企隔离提报闭环**：  
  * 内控确认后归档任务（状态推进至：已归档·待提报）；  
  * 专网提报后登记提报时间并回写官方回执编号（Official Receipt No.），任务推进至终态 已提报/已受理。  
  * &nbsp;
