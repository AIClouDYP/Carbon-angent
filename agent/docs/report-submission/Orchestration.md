# 报送任务编排详情（ReportSubmissionCenter 任务模式）

> 隶属模块：report-submission | 入口：工作台报送任务面板点击任务卡片 /「继续编排」/「提前启动」
> 对应标书：2.6.2.3（9）~（20）报送全流程、2.7.9
> 关联文档：[工作台主页](ReportSubmissionCenter.md) · [五阶段生命周期与公共支撑联系](StagesAndSupport.md) · [五阶段顶层架构规范 V5.1（目标态）](ArchitectureSpec-V5.md)

## 1. 业务场景定位

编排详情是一个报送任务的工作现场：以对话区为主战场，按**四阶段**推进（模板匹配与主体核对 → 数据采集 → 生成与校验 → 确认归档），覆盖口径适配、补缺采集、报表生成、双重校验、审核签发、导出归档、溯源全流程。每阶段产物可回看，中断可从断点继续。

## 2. 页面布局

对话区为主战场：顶部四阶段流程条（当前阶段高亮）→ 阶段输出卡片流（数据项分组/校验表/评分环形图/异常卡片/报表预览）→ 底部输入框。编排详情为全屏视图，无系统导航。

## 4. 功能点详情

> 按阶段逐项展开：交互 → 边界 → 数据 → 验收。第一版全阶段覆盖，待人工校对。

### 4.0 通用规则（跨阶段）

- **阶段推进**：每阶段产物经用户确认后锁定进入下一阶段；阶段条可回看已确认阶段的输出；
- **任务删除**：编排内未存档任务（未归档/未提报/未受理）可删除（header 删除按钮，二次确认）；已归档/已提报/已受理承载留痕与档案，不可删除；
- **上下文用量估算（O-13）**：编排对话输入区徽标展示会话上下文长度估算（k / 万 tokens 格式化），任务重置后清零；
- **工作台指令面板**：按当前阶段动态出项（每阶段固定含「本阶段说明 / 全流程进度」+ 阶段专属操作项）；
- **中断续做**：任务状态持久化，重进后从断点阶段继续。

### 4.1 阶段一：模板匹配与主体核对（O-02）

> 界面构成 = 两个信息区（三要素与模板匹配 / 用能单位概况）+ 贴底流转栏 + 两个弹窗（模板结构预览 / 编制依据明细）。

#### 1) 报送三要素（只读事实）
- **交互**：受理主管机关 / 报送频次 / 报送期次三项只读展示；填报领域不在三要素重复展示（该信息由下方「填报场景」行承载——场景名即由领域解析而来，且附报表套件说明）
- **边界**：不可编辑——三要素由报送计划确定，任务由此自动生成
- **数据**：activeTask（dept / freq / period；field 经场景解析呈现于填报场景行）
- **验收**：[ ] 三项与工作台任务卡片信息一致；[ ] 填报领域仅出现一次（填报场景行）

#### 2) 模板锁定概览
- **交互**：模板名 +「已锁定」标签 + 版本（注「任务创建时锁定」）+ 适用范围标签组；锁定语义收纳于分组标题旁「！」图标，悬浮显示（不常驻占行）
- **边界**：模板版本不可在任务内切换；改用新版需新建任务
- **数据**：templateInfo（docName / version / scopes）
- **验收**：[ ] 模板库改版后本区仍显示锁定版本；[ ] 悬浮图标可完整查看锁定语义说明

#### 3) 填报场景
- **交互**：场景在**任务创建时唯一确定并锁定**（与模板版本锁定同口径）——周期任务由报送计划的场景适配条件固定（创建时必选、未完成选择阻断创建）；临时报告弹窗多场景必选。阶段一**纯只读展示**（场景名 + 报表套件）
- **边界**：场景决定走哪套报表与免填项集合；填报领域为客观事实属性，不提供原地变更——选错场景的恢复路径 = 删除任务重建（未存档任务可删）；不做企业档案自动路由；选择器仅在场景解析不到时兜底出现（数据异常防御，指定后下游需重新确认）
- **数据**：activeTemplate.variants / activeVariant（按创建时锁定的 sceneRule 解析）
- **验收**：[ ] 报送计划创建时未完成场景选择无法提交；[ ] 阶段一面板无场景变更入口；[ ] 场景锁定后阶段二采集清单与免填项与之始终一致

#### 4) 编制依据
- **定义**：本报告全部数字换算的确定性依据包，回答三个问题——按哪份文件算（政策标准依据）、具体怎么算（换算依据）、系数取哪个值（因子选取依据）
- **构成（两个维度）**：
  - **依据来源**（三库引用，创建时锁定版本）：① 政策标准依据——规则集挂靠的标准与报送规范（standardCode → 政策标准库）；② 换算依据——计算公式与折标方法（formulaStandard → 公式库）；③ 因子选取依据——因子锁定版本与匹配链路：场景路由 / 历史映射记忆 / 置信度 / 命中记录（factorVersion → 因子库）
  - **规则参数**（四类操作项）：① 指标名映射（数据池字段 → 报表指标）② 范围规则（核算边界：纳入哪些设施/系统）③ 计算口径（主管部门口径差异）④ 粒度聚合（明细数据 → 报送期次汇总）
- **交互**：入口卡片形态（与「模板结构预览」同构：标题 + 静态引导描述 +「查看依据」CTA），点击打开明细弹窗——公式数 / 因子版本 / 格式要求 / 标准库与公式库的异常状态收纳于弹窗内，面板不重复展示
- **边界**：模板持引用声明、规则集本体在标准库/公式库/因子库——引用与本体分离，本体改版不影响在途任务；换算由规则引擎按锁定规则执行，AI 不参与算数
- **数据**：caliberInfo（declaration / ruleParams / ruleMappings / ruleClauses / formatReqs / formulas，分组化结构与弹窗分组一一对应）
- **验收**：[ ] 三类依据可分别追溯至标准库 / 公式库 / 因子库；[ ] 未收录公式时给出可读提示而非空白；[ ] **演示案例内容与真实《用能单位能源利用状况报告格式》（99输出材料/08报告提报/附件2 docx）逐项核对一致**——表1 及表2/3/7/8/26/27/28 已按官方版式 blocks 还原（表2 四层表头 + 甲乙丙/1~9/丁 栏次行 + 39 品种代码、表3 加工转换双层表头 + 39 品种、表7 项目/子项两列 13 行、表26 kv 说明行、表27 双组六列配对、表28 16 条自查项），各领域表号范围、格式要求（封面黑体一号 / 正文仿宋三号 / 1.5 倍行距 / 封二四项）、条款引用（编制说明 4~6 等）；**第二批待办**：表9~19/23 基本情况表计量单位预置与 blocks 化、表4/5/6 版式核对

#### 5) 合规风险上浮（三条预警线）
- **依据标准废止**：上浮到面板（必须处理的合规风险）；正常状态下依据标准不下沉到面板（在模板结构预览中查看）——「未收录属常态，不打扰」
- **标准更新**：仅提示标准库已有更高生效版本，在途任务仍按锁定版本执行
- **模板库改版**：提示在途任务仍按锁定版本执行，改用最新版需新建任务
- **验收**：[ ] 三类预警各自独立出现、互不干扰；[ ] 无风险时面板无噪音

#### 6) 模板结构预览（弹窗）
- **交互**：面板卡片入口 / 指令面板 / 对话指令（「模板预览 / 模板结构 / 报表清单」）三通道打开；内容 = 章节结构（TemplateSectionsPreview 组件）+ 报表张数 + 格式要求；**官方版式还原**——章节声明 `blocks` 版式块时按报送表样渲染为**一张连续表格**（kv 主体信息区 24 列网格统一标签列宽 / 指标表复用章节 columns+rows 单一来源 / `groupHeads` 双层表头 / `headerRows` 任意层级表头 + 栏次行（甲乙丙/1~N）/ tail 表尾签署行，各区块以 colspan 网格共用同一表格不再断开；colgroup 24 等分 + table-layout fixed 对齐，min-width 1080px 配合横向滚动；单元格自动换行、不拆分原文），blocks 存在时基本信息 chips、用途/数据来源元信息与「概况」角标退位不渲染；未声明 blocks 的章节仍按 columns+rows 单表渲染
- **边界**：只承载「本任务锁定模板的章节结构」——模板全称 / 版本 / 编制依据 / 依据标准已在阶段一面板展示，弹窗内不重复
- **数据**：previewSections / templateSections / formatReqs
- **验收**：[ ] 弹窗章节结构与阶段二采集清单章节一一对应

#### 7) 编制依据明细（弹窗）
- **交互**：全部内容按三个分组归类（来源行「引用自报告模板」为弹窗级上下文不占编号）——**❶ 核算规则**（数据怎么算：编制依据名称 / 依据标准 / 四类参数）、**❷ 成文格式**（文档怎么排：封面字体 / 行距 / 落款）、**❸ 多口径适配**（给谁报怎么转：部门差异，仅列与主口径的不同项）；数据异常时以行内空态呈现。**严格按模板（附件2）要求显示**——附件2 未声明的引用键（公式标准 / 因子版本）不展示，公式 / 因子属平台内部配置
- **边界**：换算由规则引擎执行，AI 不参与算数；解析优先标准库缓存，缺失时从服务层种子常量兜底（不受缓存覆盖影响）；**公式本体不在本弹窗展示**——模板仅引用标准键，公式明细在公式库管理页按标准检索查看，任务流程中实际应用的公式见阶段三各章节「口径换算依据」；格式要求自模板结构预览迁入——本弹窗完整承载「这份报告按什么规范编制」（数据口径 + 成文格式）
- **数据**：caliberInfo（declaration / ruleParams / ruleAvailable / formatReqs）
- **验收**：[ ] 四类参数齐备且可读；[ ] 引用公式可追溯至公式库

#### 8) 用能单位概况（字段集版 · 能源利用状况报告）
- **交互**：分组卡片（基础信息 / 经济指标 / 签署信息）默认收缩，存在待补录项的分组自动展开；分组头显示「已带出/待补录」计数；字段由企业档案带出、可直接编辑；「标准带出」来源标签仅在非默认来源时显示（避免逐字段噪音）
- **经济指标表**：本期 / 上年双输入，同比变化率自动计算；波动超 ±20% 时合规校验将提示补变化情况说明（面板预告知规则）
- **签署信息**：渲染至各报表页脚；封二另需单位名称（盖章）、编写人员名单、负责人签字（盖章）
- **顶部覆盖标签**：必填 N 项 · 已带出 M 项 · 待补录 K 项
- **数据**：profileGroups / profileValues / profileCoverage
- **验收**：[ ] 待补录分组自动展开；[ ] 同比变化率随输入实时计算

#### 9) 用能单位概况（简版 · 其他报告类型）
- **交互**：基础字段直编 + 物理边界标签编辑（输入回车添加、可删除）+ 责任填报部门（标注「填报属性」）
- **数据**：activePanels[1]
- **验收**：[ ] 边界标签回车添加、删除即时生效

#### 10) 阶段流转（贴底栏）
- **交互**：提示「模板匹配与主体信息确认无误后进入数据采集」+ 确认按钮 → 阶段二（推送阶段引导语）
- **边界**：阶段一无硬性闸门（对比阶段二缺项清零闸门），依赖用户人工确认
- **验收**：[ ] 确认后正确进入阶段二且阶段条高亮同步

### 4.2 阶段二：数据采集与补录（O-03）

> 界面构成 = 进度与提示区 + 章节采集清单 + 贴底流转栏 + 表格导入弹窗。

#### 1) 采集进度与缺项提示
- **交互**：进度条（已采集 N/M 项）+ 缺项清单条（缺项名称罗列，引导点击「去补录」查看缺失原因与补录建议）
- **数据**：collectRequired / collectMissing / collectRate
- **验收**：[ ] 进度百分比与缺项数勾稽一致

#### 2) 本场景免填项提示与条件性表格自动判定
- **交互**：单独说明条（不计入进度与主列表）——两类：① 场景免填项（填报领域按附件 2 规范仅报对应场景表格，列明免填项名称）；② **条件性表格自动判定**（如表 6 数据中心：按企业档案判定「无全年电力消耗 500 万千瓦时及以上的数据中心」→ 整表标为不适用并显示判定依据）
- **边界**：让用户感知"系统已考虑过"，又不干扰应报清单；条件判定的依据（企业档案字段）需在说明中可见
- **数据**：collectNa
- **验收**：[ ] 免填项不计入进度分母；[ ] 条件性表格按企业档案自动判定并显示判定依据

#### 3) 章节采集清单（按报表章节分组）与在线填报
- **交互**：进度行右侧「全部章节 / 仅看缺项（N）」过滤切换（缺项聚合视图，默认全部章节）；章节头（名称 + 状态标签：缺项 / 就绪 / 不适用 + 字段数）展开收起；展开后显示章节级数据来源 + 字段明细表（# / 数据项名称 / 单位 / 填写口径 / 上期参考值 / **本期值**）；缺项章节提供「导入表格」（直达导入弹窗并预选）与「去补录」（发起对话引导）
- **在线填报**：缺项章节的「本期值」列为可填输入框——直接填写即完成采集（全部字段填完后章节状态自动联动为「已采集」并提示），覆盖表 7 节能目标进度、表 8 节能改造项目等**管理类表格**（数据池无法自动引用、导入性价比低的场景）；已采集章节字段只读回显
- **边界**：主体类章节回指阶段一「用能单位概况」（不重复罗列），修改需返回阶段一；已导入字段显示「已导入」标签；在线填报与导入 / 对话引导三通道并存
- **数据**：chapterItems / visibleChapters / chapterFilter / collectedSnapshot（章节状态联动 refreshItemStatus）
- **验收**：[ ] 主体章节正确回指；[ ] 字段明细含上期参考值；[ ] **缺项章节在线填写后章节状态自动联动为已采集、进度与闸门同步更新**；[ ] 「仅看缺项」下缺项清零时显示就绪空态、计数徽标同步归零

#### 4) 表格导入补录（弹窗 · 补缺主渠道）
- **交互**：目标章节默认首个缺项章节；缺项章节头「导入表格」可直达（预选该章节打开弹窗）；上传 Excel（可「另存为 CSV」）/ CSV，或「下载导入模板」——按所选章节字段生成表头 CSV（UTF-8 BOM），无现成表格的用户填模板后导回，表头与字段精确匹配；系统自动建议字段映射并显示映射置信度；确认后数据写回并刷新进度
- **样式参照**：问题驱动三段式（问题清单/佐证上传/逐项确认，见产品碳足迹阶段6与零碳工厂阶段3）经评估**不整体采用**——报告提报阶段二为表单驱动（结构化报表章节、单章节数十行字段），保留「章节折叠 + 字段表」骨架；三点全部吸收：① 模板下载（导入弹窗「下载导入模板」，按章节字段生成 CSV）② 章节级导入入口（缺项章节头「导入表格」直达并预选）③ 缺项聚合视图（进度行「全部章节 / 仅看缺项（N）」切换——仅缺项时清单收敛为待处理章节，缺项清零显示就绪空态）
- **数据**：importVisible / importMapping / importConfidence / importTargetFields
- **验收**：[ ] 导入写回后「已导入」标签与进度即时更新；[ ] 缺项章节「导入表格」直达后目标章节已预选；[ ] 下载的模板表头与本表字段一一对应，原样填值导回后映射全部精确命中

#### 5) 阶段流转（完整性闸门）
- **交互**：贴底提示「完整性闸门：缺项清零后方可进入生成与校验」+ 按钮在采集率 100% 前禁用
- **边界**：与阶段一的"人工确认"不同，本阶段为**硬闸门**
- **验收**：[ ] 缺项未清零时按钮不可点

### 4.3 阶段三：生成与校验（O-04 口径适配 / O-05 报表生成 / O-06 校验评分 / O-07 异常处置 / O-08 规范合规）

> 界面构成 = 校验区（置顶折叠）+ 章节内容预览（采纳/重生成）+ 贴底流转栏；弹窗：整篇预览（含 AI 改写）。

#### 1) 校验区（置顶）
- **交互**：校验在「确认生成结果」时自动执行，无需切换阶段即可查看结果与处置；头部（通过 x/total + 摘要）点击展开/收起明细；存在阻断异常时自动展开
- **校验状态总览（客观计数，不做加权评分）**：文案「共 N 项规则 / 已通过 M 项 / 待处置 X 项（阻断 a · 建议 b）」+ 快捷过滤 chips（全部 / 待处置 / 各分组 pass/total）——避免伪精确与双闸门口径
- **校验明细表**：按分组（格式合规 / 数据逻辑）展示，校验项 / 结果 / 阈值 / 判定四列；非阻断项标「建议项」；悬停可看规则说明与判定依据
- **空态**：全部通过时显示"全部校验项通过，无待处置异常"
- **数据**：checkSummary（total / pass / groups）/ verifyPendingCount / verifyBlockingCount / verifyFilter / verifyGroups / verifyAnchors
- **验收**：[ ] 待处置（阻断）项与贴底栏闸门联动；[ ] 建议项不阻断；[ ] 分组过滤计数与总数一致

#### 2) 异常卡片与处置（六种方式 + 转人工）
- **交互**：卡片（等级标签 / 标题 / 描述 / AI 处置建议）+ 确认处置 / 转人工核实 /「其他处置方式」下拉（对话补数 / 确认使用 / 确认正常 / 修正报表 / 更新口径映射 / 忽略，支持批量）；转人工后显示责任移交说明（核实结论回填后解除标注，不再阻断本环节）
- **边界**：处置结果写入修订留痕
- **数据**：activePanels[3].cards / cardActions
- **验收**：[ ] 转人工后该卡片解除阻断；[ ] 每次处置留痕

#### 3) 章节内容预览（采纳与重生成）
- **交互**：章节展开后主视图 = 将写入报告正文的内容（数据表 + 叙述 + 字数），可「采纳」（采纳后显示 ✓）/「重新生成」；长叙述折叠可展开全文；详情 = 口径换算依据（默认收起）：指标 / 原值 / 换算规则 / 适配值四列——换算规则悬停显示公式库与因子库引用；适配值悬停显示因子溯源（因子名 / 取值 / 来源池 / 场景 / 置信度 / 历史匹配命中）
- **边界**：换算由确定性规则引擎执行、结论预计算，AI 不参与算数，明细供核查溯源；附件报表不做文字改写（提示条引导至整篇预览）
- **数据**：stageBodyChapters / adopted / regenNarratives / adaptFactorMap
- **验收**：[ ] 换算依据悬停可追溯至公式库与因子库；[ ] 重新生成不覆盖已采纳章节

#### 4) 整篇预览（弹窗）
- **交互**：按定稿版式通读全文；段落级 AI 改写为待审改动（明确标注 mode 与风格），需人工接受或拒绝、不静默写入正文；支持导出 PDF
- **改写动作**：AI 润色 / 扩写 / 精简 / 重写四种，作用于叙述性正文；附件报表为纯数据，不做文字改写
- **风格控制**（两层入口、共用一套参数）：
  - **画布顶部常显**「AI 改写风格」——只保留**文体**一维（公文正式 / 专业严谨 / 简洁直述 / 汇报说明），位于报告封面标题与章节统计下方，作用于全部章节，选择自动记忆（localStorage）；**受众不由用户选**：受理部门自动取当前任务（报送计划的主管部门 / 临时报告的本级）并只读展示；
  - 左侧对话指令——如「把第二章改成对主管部门汇报的正式口径」「这段改成简洁直述」，支持章节（第2章 / 第二章 / 表2）、动作、文体、受众识别，指令中带章节与动作时直接对该章执行改写；
- **改写护栏**（风格只改表达、不改数）：数值一致性（与规则引擎换算结果不一致的改动**阻断接受**）/ 术语规范 / 篇幅约束（0.6~1.6×）三档；被阻断的改动只能重新生成或拒绝
- **留痕**：待审改动记录 mode 与风格（如「AI 润色 · 公文正式 · 主管部门」），接受后写入正文并随任务分片持久化
- **边界**：待审改动与已接受正文按任务 id 分片持久化，关闭弹窗 / 刷新不丢失；风格选择单独持久化
- **数据**：aiPolish / aiNarratives（localStorage）、polishTone / polishAudience / POLISH_TONES / POLISH_AUDIENCES / POLISH_STYLE_KEY
- **验收**：[ ] AI 改动一律经人工确认后生效；[ ] 改动导航（「下一处改动」）可用；[ ] 切换文体后生成内容与留痕标签同步变化；[ ] 对话指令可设置文体并按需对指定章节执行改写；[ ] 数值不一致的改动无法接受

#### 5) 阶段流转
- **交互**：贴底提示两态（"校验发现 N 项异常待处置，清零后方可产出文件" / "校验无阻断异常，确认后进入文件产出"）+ 按钮在 blocking > 0 时禁用
- **验收**：[ ] 异常清零后闸门放行

### 4.4 阶段四：审核签发与归档（O-09 三级审核 / O-10 导出归档 / O-11 修订留痕 / O-12 数据溯源链）

> 界面构成 = 文件卡片（渲染 / 导出）+ 指标修订表 + 修订留痕 + 多级审核 + 签发凭据 + 贴底流转栏 + 数据溯源链弹窗。

#### 1) 文件卡片与导出
- **交互**：文件名（已按锁定模板渲染 · 含数据表格与图表）+「预览」（整篇预览弹窗）+「导出报告」下拉（5 种格式，各附适用说明；共享导出服务，统一嵌入元信息水印）；格式校验通过提示条
- **验收**：[ ] 各格式导出均含水印元信息

#### 2) 指标预览与修订（修订重校）
- **交互**：指标行（可修订 / 派生值标签；可修订项数值输入、派生值只读）；修订后自动重跑勾稽类校验项；重校未通过则签字阻断，可选「标记例外并留痕」（例外放行后显示标签）
- **边界**："修订不重校"会使校验闸门形同虚设，故勾稽类强制重跑
- **数据**：activePanels[4].metrics / previewCheck / previewException
- **验收**：[ ] 修订触发勾稽重跑；[ ] 例外放行留痕可查

#### 3) 修订留痕
- **交互**：时间线列表（时间 + 内容 + 操作人标签）；各阶段的人工动作（修订 / 处置 / 口径确认 / 例外放行）自动追加
- **验收**：[ ] 人工动作无遗漏入痕

#### 4) 多级审核（三级）
- **交互**：填报人自查 → 部门负责人审核 → 碳管理师复核时间线；每级：通过 / 退回修改 / 添加批注；头部显示 x/3 级通过；全部通过后方可签字归档；退回后需修改并重新送审
- **审批链来源**：审批层级（无需审批 / 一级 / 二级 / 三级）与各节点审核人在**创建任务时确定**（任务级 approval 配置），编排内**只读展示、不可切换**；无需审批时直接签发归档，多级时审核节点按层级裁剪（L1 填报人自查 → L2 部门负责人审核 → L3 碳管理师复核）；节点显示创建时锁定的审核人，已审核的以审核记录为准
- **数据**：auditFlow / auditSummary / activeTask.approval（mode + chain）
- **验收**：[ ] 未全部通过时签字禁用；[ ] 批注随级显示；[ ] 审批模式与节点在编排内不可切换

#### 5) 签发凭据（防篡改）
- **交互**：签字归档时生成内容指纹（已哈希锁定：指纹 / 签发时间 / 签发人 / 算法）；「校验完整性」随时可验——检出签发后的任何改动并显示当前指纹与原因
- **验收**：[ ] 签发后改动被完整性校验检出

#### 6) 阶段流转（归档闸门）
- **交互**：贴底提示三态（审核未通过 → 需完成审核 / 勾稽未通过 → 先平衡数值或标记例外 / 可归档 → 确认后哈希锁定、修订入口关闭、不可撤销）+「签字确认并归档」
- **边界**：归档后按"部门+期次"命名存储，登记至碳报告中心（查看/下载统一在该模块），任务置「已归档·待提报」——签字归档 ≠ 提交成功，提报状态由人工登记推进（工作台任务卡片：登记提报 → 已提报、登记受理 → 已受理）
- **验收**：[ ] 三态提示正确切换；[ ] 归档后修订入口关闭

#### 7) 数据溯源链（弹窗）
- **交互**：L1 报表 → L2 口径适配 → L3 模块数据池 → L4 原始采集（**四级**，逐级下钻）；每级含数值 + 规则来源 + 时间戳 + 责任方
- **边界**：原「L3 标准化级」已移除（该层无独立数据源，口径统一语义并入 L2）；**取不到数据时如实标注「本层无记录」，不用演示值兜底**（归档阶段证据不得由演示值兜底）
- **数据**：traceTree / traceVisible / traceEmptyNode
- **验收**：[ ] 四级链路可逐级下钻至原始采集；[ ] 无数据层显示「本层无记录」而非演示值

#### 8) 提报状态跟踪（已归口报告大厅）
- **现状**：部门 × 期次提报看板（含单元格详情与状态枚举）**已整体移除**——看板数据与报告列表不联动（期次体系对不上），提报状态统一由报告列表三态表达（已归档·待提报 / 已提报 / 已受理）
- **边界**：提报状态跟踪属大厅总览能力，已归口报告大厅；本页只承接工作台任务卡片上的登记动作（openSubmitReg / confirmSubmitReg）
- **验收**：[ ] 编排页不出现看板入口；[ ] 登记提报 / 受理后任务三态正确推进

> **数据项与来源**：见 [_data-dictionary.md](../_data-dictionary.md)。编排态关键字段：阶段状态机（四阶段/八环节/九状态）、数据项采集进度、口径适配记录、校验结果集（客观计数）、审核流记录、修订留痕、归档元信息。

### 4.5 全局边界

- 校验存在阻断项（未通过的必须项）→ 阻断提报，必须完成异常处置；
- 规范偏差 → 偏差卡片附引用条文与修正建议，全部匹配后才能生成合规声明；
- 审核退回 → 触发重新校验与修订流程；
- 用量估算 → 按中文字符≈1.5 token 折算，为水位提示而非精确计数，非计费计量（接入真实大模型后替换为 API usage 统计）。

- [ ] 四阶段推进顺序正确，各阶段可回看
- [ ] 校验评分与阻断逻辑正确（<60 阻断）
- [ ] 异常卡片六种处置可用且批量生效
- [ ] 三级审核全部通过后报表锁定不可修改

- [ ] 编排对话 token 估算徽标随对话增长，任务重置后清零

> 各阶段与支撑的引用关系视图（谁在哪个阶段取用什么）见 [五阶段生命周期与公共支撑联系](StagesAndSupport.md)；本节只登记对接要求，不重复关系图。

|---|---|---|---|

### 5.1 各支撑的关键要求

**① 政策标准库（policyStandardService）**
- 引用与本体分离：模板仅持引用声明（standardCode / formulaStandard / factorVersion），规则本体在标准库——同一规则集可被多模板复用，政策升版一处生效；
- 参数化结构：每个规则集含四类参数（指标名映射 / 范围规则 / 计算口径 / 粒度聚合）+ 执行映射（指标 ↔ 数据源 ↔ 因子 ↔ 公式）+ 条款引用（clauseRefs 溯源到条文）；
- 部门级口径条目独立成条（按 issuer 区分）：新增报送部门只需标准库追加条目，多口径转换引擎不改；
- 种子自动入库：ensureSeed 幂等（SEED_VERSION 升版时向已有缓存合并新种子，已参数化条目不覆盖用户编辑）；
- 现行性核验：模板引用的标准在标准库中检索（missing / obsolete / ok 三态），废止上浮到编排面板。

**② 排放因子库 / 匹配服务（factorMatchingService）**
- 换算用因子必须可追溯：因子 ID、取值与单位、来源池、匹配场景、置信度、是否命中历史映射记录——六要素随换算结果展示；
- 企业级映射记忆：同一企业同类指标的历史匹配可复用（memoryHit）；
- 单位归一：活动数据单位与因子单位不一致时自动归一并在换算依据中标注。

**③ 公式库（FormulaLibrary）**
- 公式必须可执行、可追溯：appliedStandard 关联标准，参数含符号/含义/单位/来源；
- 幂等补种：内置公式按 id 判重补入已有缓存；
- **已知限制（细化设计须解决）**：懒初始化——数据在首次打开公式库管理页时才写入存储；智慧报告直接读取会得到空集。应将公式库默认数据提取为共享数据模块，消费方读取时保证已初始化。

**④ 平台模板库（platformTemplates）**
- 模板声明内容：docName / version / reportType / periods / prefill / scopes / matchFields / variants（含 conditions 场景条件 + sections 报表结构 + body 正文骨架）/ caliber 引用声明；
- 结构指纹升级：scope、caliber.standardCode、body/sections/variants 内容哈希任一变更 → 缓存条目自动以新结构覆盖（代码维护结构、界面仅编辑业务字段）；
- 模板锁定快照须包含完整 caliber 引用对象（standardCode 等），不允许仅快照名称字符串。

**⑤ 导出服务（exportService）**
- 5 种格式共享同一导出框架（一次渲染多格式输出）；
- 所有格式统一嵌入元信息水印（来源智能体 / 任务 / 期次 / 指纹），用于溯源与防篡改佐证。

**⑥ 离线导入服务（importService）**
- 零依赖 CSV 解析（Excel 引导「另存为 CSV」），字段映射自动建议并给出置信度，确认后写回采集清单并刷新进度。
- **细化设计硬点（已登记）**：多级表头映射——真实报表（如表 2 能源消费结构表为 39 品种 × 14 列多层表头：消费量下分合计 / 工业生产 / 用于原材料 / 非工业生产 / 运输工具）的导入 Excel 存在合并单元格表头，单层字段映射建议无法覆盖，需支持多级表头解析与列组映射。

**⑦ 签发引擎（signService）**
- 签发生成内容指纹（算法 / 签发人 / 时间随凭据存储），支持随时重算比对、检出签发后任何改动；
- **生产化转换点**：原型为前端指纹模拟，细化设计替换为服务端签名（配合防篡改存储）。

**⑧ 碳报告中心（跨模块）**
- 归档时按「部门 + 期次」命名登记，分配报告编号回写任务；
- 提报状态登记（提报 / 受理）与工作台任务卡片联动推进。
