# 智慧报告工作台（/#/agent-center/apps/report-submission）

> 模块：report-submission | 主文件：views/ReportSubmissionCenter.vue（约 5500 行，含两种页面模式）+ components/ScenarioMatch.vue
> 对应标书：2.6.2.3 区域能效诊断、2.7.9 能碳多源数据智慧报告智能体
> 页面模式：本文档覆盖**工作台主页**（两页签 + 对话欢迎态）；进入具体报送任务后的**编排详情**另见 [Orchestration.md](Orchestration.md)；智慧报告对基础支撑（标准库/因子库/公式库/模板库等）的依赖与细化设计要求见 [Orchestration.md](Orchestration.md) 第 5 节

## 1. 业务场景定位

工作台是智慧报告智能体的首页与任务管理中心：面向企业碳管理员与园区报送负责人，提供报送任务的集中管理（本期应报/其他任务）与报送计划配置（日历）；从任务列表点击任务或「继续编排」后进入[编排详情](Orchestration.md)。

## 2. 页面布局

本页为工作台主页（home 模式）；点击任务进入编排后的沉浸态（active 模式）布局见 [Orchestration.md](Orchestration.md)。主页三栏：

```
┌──────────┬────────────────────────────┬──────────────┐
│ 历史对话  │  对话区（主体）             │  右栏窄栏     │
│ (可收缩) │  欢迎语 + 新手引导          │  ┌──────────┐│
│          │  快捷命令 / 输入框          │  │报送任务页签││
│ 对话记录 │                             │  │日历页签   ││
│ 切换/删除│                             │  └──────────┘│
└──────────┴────────────────────────────┴──────────────┘
```

- 左：历史对话栏（可收缩为窄边条，记录/切换/删除会话）；
- 中：对话区，欢迎态承载引导与指令入口；
- 右：两页签工作台（报送任务 / 日历），日历页签含「新建报送计划」按钮；
- 弹窗：新建报送计划（含关联模板即时解析，解析不到时阻断并提供「前往平台模板库」跳转）；
- 抽屉：存证底卷（已归档/已提报/已受理任务的凭证直读入口，见 R-13）。

## 4. 功能点详情

> 对照第 3 节清单逐项展开：位置（见第 2 节布局）→ 交互 → 边界 → 数据 → 验收。编排过程异常统一见 [Orchestration.md](Orchestration.md) 第 6 节。

### R-01 历史对话栏（左栏）
- **交互**：
  - 自动记录：发送消息后保存会话
  - 恢复上下文：点击条目切换会话，可删除
  - 新建对话：开启空白会话
  - 收缩：边条可收起为窄边条
- **边界**：窄屏（<1100px）自动隐藏
- **数据**：conversationHistory（title / timestamp / conversationId，本地持久化）
- **验收**：[ ] 历史对话自动记录，切换对话恢复上下文，可收缩窄边条

### R-02 对话区（中栏·主体）
- **交互**：
  - 引导：欢迎语 + 新手指引（OnboardingGuide）
  - 查询类能力（历史报告 / 进度 / 缺漏）定位为**通用对话能力**：指令面板（灯泡，3 条）与对话直接可用，不设专门按钮——历史报告查询读取碳报告中心归档做对话式问答摘要，完整列表与下载在碳报告中心
  - 对话指令：输入「新建报告」打开 R-05 弹窗；未知指令回复可用指令清单；回答同时联动右栏页签（进度类→报送任务，日历类→日历）
- **数据**：messages、briefStats / urgentList（由 reports 实时派生）、org_carbon_reports_v2（历史报告查询，碳报告中心归档数据）

### R-03 工作台两页签（右栏容器）
- **交互**：
  - 页签切换：报送任务 / 日历，状态记忆保持
  - 部门筛选：日历页签按计划的受理主管部门过滤（选项由现有计划动态去重生成），默认显示全部计划
  - 滚动收敛：两页签均为内容区局部滚动——报送任务在分组列表内滚（见 R-11），日历顶部说明/工具条/部门筛选固定、仅计划卡片组内部滚动（容器 flex:1 自适应剩余高度，筛选无结果时空态提示）
- **数据**：rightPanel、calDeptFilter
- **验收**：[ ] 两页签切换状态保持；[ ] 日历页签滚动仅发生在卡片组内，顶部说明与筛选始终可见

### R-04 报送任务面板（右·报送任务页签）
- **交互**：
  - 分区：本期应报（日历自动生成，自动置顶，附提报截止倒计时）+ 其他任务（已提报 / 手动 / 临时）；本期应报按截止日升序排列
  - 检索：搜索（名称 / 类型 / 主管部门 / 期次）+ 状态筛选（计数实时统计）；无结果时区分提示"未找到匹配的报告"
  - 进入编排：点击任务卡片或「继续编排」→ 编排详情（见 Orchestration.md）
  - 任务删除：未存档任务（编排中 / 待提报）可删——首页"其他任务"卡删除图标与编排 header「删除」按钮同规则（二次确认）；已归档 / 已提报 / 已受理不可删
  - 归档联动：签字归档后任务置「已归档·待提报」（文件已锁定、登记至碳报告中心并回写报告编号），卡片附「碳报告中心 ↗」跳转（携带 focus 参数，目标页高亮定位该条目）
  - 主数据持久化：reports / submissionCalendar 变更自动写回本地（rs_reports_v1 / rs_calendar_v1），刷新不丢现场；mock 结构版本（seed）变更时旧缓存失效回退演示数据；**旧 seed 载入的内存数据禁止回写**（防止热更新时旧数据被按新 seed 写回形成脏缓存）
  - 提报状态维护：已归档 →「登记提报」（提报方式 / 时间 / 凭证号 / 附件凭证）→ 已提报 →「登记受理」（受理时间 / 文号 / 附件）→ 已受理（闭环）；两动作共用统一弹窗（标题栏 → 文字说明 → 表单字段 → 附件凭证 → 按钮区），提报状态统一由任务三态表达（已归档·待提报 → 已提报 → 已受理）
  - 按钮分层：编排推进类（继续编排 / 去补录 / 开始提报 / 确认归档）实底强调（主功能）；提报状态推进类（登记提报 / 登记受理）与查看类（查看归档）描边弱化（人工辅助动作）——风格按动作性质分层，跨区一致
  - 卡片三行布局：标题行（urgency 点 + 名称）/ 标签与操作行（异常·倒计时·状态徽标靠左，按钮靠右）/ 进度行（meta · 进度条 · 百分比，常显不再悬停展开）
- **数据**：reports（status / deadline / progress / issues / earlyKey 等）
- **边界**：提报状态由人工登记 / 后端回执驱动——签字归档只是文件定稿，不等于提交成功；政府回执无 API 时以人工录入为准
- **验收**：[ ] 点击任务/继续编排均能进入编排详情；[ ] 归档后任务为「已归档·待提报」，登记提报/受理后任务状态正确推进

### R-05 临时报告创建（右·报送任务页签按钮 → 弹窗）
- **交互**：
  - 触发：右栏「临时报告」按钮或对话指令「新建临时报告」（智能体回复提示 + 打开弹窗）
  - 填写：弹窗（报告类型——按所选时间维度（周 / 月 / 年 / 自定义）自动过滤，选项内展示适用场景与支持周期（模板 periods）；报告名称——按期次自动生成可改；时间维度（周 / 月 / 年 / 自定义）——年度/半年度/季度/月度/**自定义**，联动期间控件形态（年度→年份选择器；月度/季度/半年度→月份选择器，半年度与季度按月份归纳；**自定义→年月日起止区间选择器 daterange**，期次按「起日 ~ 止日」表达）；填报场景——多场景模板创建时必选（写入 sceneRule）；**审批模式**——审批层级（无需审批 / 一级 / 二级 / 三级，默认**无需审批**）+ 选择多级后展开审批节点与审核人（**节点名称默认与平台节点一致、可编辑**；**审核人为下拉选择企业人员**，选项取自组织资源库带出的用能单位概况人员，支持自行录入新人员；创建时锁定，写入任务 approval）；备注选填）——与「新建报送计划」同为新建类动作，统一弹窗形态
  - 创建：确认后写入任务列表（period 按维度归纳、freq 记录时间维度（周 / 月 / 年 / 自定义）、期望完成日 deadline、remark 与 sceneRule 随任务留痕）并切至报送任务页签
- **边界**：非周期、无提报窗口，不入报送日历
- **数据**：newReport、calTypeOptions
- **验收**：[ ] 临时报告创建成功后不入日历，出现在报送任务「其他任务」区

### R-06 期次自动派生（右·日历页签，自动）
- **交互**：
  - 触发：进入页面时检查全部启用计划（生产环境为后端定时任务）
  - 生成规则：`生成日（nextGen）≤ 当日` 且该期次任务不存在 → 按频次计算期次名与生成日（buildPeriodMeta）→ 自动创建任务（状态「编制中」、进度 5%、阶段二，随计划带入模板锁定、场景规则与审批配置 approval）
  - 判重规则：同计划同期次只派生一次——按 `earlyKey（计划 id）` 或 `受理部门 + 期次（dept + period）` 双重判重，已在途/已生成则跳过
  - 对话播报：派生成功后向对话区推送「【报送排期·自动生成】」消息（含生成日、期次名、主管部门与频次、提报截止日）并滚动到底部
  - 期次推进：计划的 `nextGen / nextPeriod / nextName / windowEnd` 指向下一期次；原型由计划数据维护（演示数据已将月度计划推进至 11 月期次、季度计划推进至 2027Q1，避免重复派发已过期次），生产环境由后端在期次完成后滚动推进
- **边界**：停用的计划不参与派生（见 R-08 计划管理）；派生只创建任务、不改计划状态；派生任务与手动创建任务同权（可编辑 / 删除 / 进入编排）
- **数据**：submissionCalendar（dept / reportType / freq / nextName / nextPeriod / nextGen / windowEnd / enabled）、reports.earlyKey（计划 ↔ 任务去重键）
- **验收**：[ ] 生成日已到的启用计划自动派生任务并推送对话消息；[ ] 同期次重复进入页面不产生重复任务；[ ] 停用计划不再派生

### R-07 提前启动（右·日历页签）
- **交互**：
  - 触发：日历页签对未到期计划手动启动
  - 行为：实例化下期草稿任务，成功后切至报送任务页签
  - 在途防重（Idempotency Guard）：该期次已有在途任务（提前启动或自动派生）时，按钮态前置为「查看在途任务」并定位跳转，杜绝重复孤儿任务
- **边界**：按 earlyKey 去重，重复启动给出提示
- **数据**：earlyKey（计划 id ↔ 任务去重键）
- **验收**：[ ] 提前启动能进入编排详情且不产生重复任务

### R-08 新建报送计划（右·日历页签按钮 → 弹窗）
- **交互**：
  - 演示默认：打开即选中「能源利用状况报告」（演示主线案例）并触发预填
  - 自动预填：选定报告类型后预填主管部门 / 频次 / 首次期次（当前月）/ 提报窗口（期次次月起 N 天，各类型天数不同）
  - **场景适配必选**：多场景模板的场景条件未全部选择时阻断创建——场景在计划创建时唯一确定，期次任务自动命中，不在编排阶段后移决策
  - 预填三级策略：① 模板 prefill 配置优先（零代码接入）→ ② 大模型语义预填（原型以规则模拟）→ ③ 留空手填；均可手动调整
  - **审批模式**：创建时确定审批层级（无需审批 / 一级 / 二级 / 三级，默认**无需审批**）——选择多级后展开审批节点与审核人（**节点名称默认与平台三级审核链一致、可编辑**；**审核人为下拉选择企业人员**（组织资源库带出的用能单位概况人员，支持自行录入新人员））；随计划保存，期次任务按此链逐级执行，全部通过后方可签字归档
  - 模板联动：选定类型即时解析关联模板，场景适配按模板 variants 动态渲染；类型下拉仅列支持周期报送的类型（periods 驱动，选项内展示适用场景与支持周期）；报送频次选项由模板 periods 约束（预填值不在范围内时回落第一项）
  - 提交：校验通过后创建日历规则（含 templateId / 场景路由），页签立即出现新计划
  - 计划管理：日历卡片支持停用 / 启用（停用后停止期次自动派生、提前启动不可用，已生成任务不受影响）与删除（二次确认；已派生任务保留，仅停止后续派生）
- **边界**：解析不到模板 → 阻断创建并附「前往平台模板库」跳转；提报窗口截止日早于开始日 → 提交拦截；模板库改版 → 在途任务按锁定版本执行（templateDrift，展示于编排详情）
- **数据**：calForm、calTemplate / templates[].prefill / variants（platformTemplates.js）、submissionCalendar
- **验收**：[ ] 打开弹窗默认选中「能源利用状况报告」且部门/频次/窗口自动预填；[ ] 三级预填策略正确且均可手动调整；[ ] 解析不到模板时无法创建计划；[ ] 模板库更新时在途任务收到锁定版本提示；[ ] 计划停用后不再派生、删除后已生成任务保留

- **验收**：[ ] 三个入口点击有「开发中」提示，不产生副作用

### R-10 上下文用量估算（中栏输入区）
- **交互**：
  - 展示：输入区徽标显示当前会话上下文长度估算值（k / 万 tokens 格式化），有消息时才出现
  - 清零：新建对话后估算值清零
- **边界**：按中文字符≈1.5 token 折算，为水位提示而非精确计数，非计费计量（tooltip 已注明）；接入真实大模型后应替换为 API 返回的 usage 统计
- **数据**：estimatedTokens（由 messages 派生）

## 附：报告编制详情的两种展现形式（2026-10-20）

同一份报告编制任务支持两种详情形态，由任务字段 `detailMode` 决定：

| 形态 | detailMode | 右侧内容 | 特征 |
|---|---|---|---|
| **流程驱动式**（原有）| `guided` | 四阶段：确认基础信息 → 采集数据 → 报告生成 → 报告归档 | 顶部阶段步骤条，按阶段逐步推进；对话承担阶段引导与追问 |
| **成稿校核式**（新增）| `document` | **直接渲染完整报告**（按选定模板 + 预填数据），无阶段 | 顶部显示「确认进度 N/M」，点击任一字段/行可在左侧对话定位来源与取值；字段级状态（已确认 / 待确认 / 待补录）；底部：重新生成 / 全篇校验 / 生成定稿 |

- **布局一致**：两种形态均为「左对话 + 右结果」，仅右侧组织方式不同。
- **数据一致**：共用同一 `reports[]` 记录（字段、模板、审批链、归档逻辑相同），切换形态不丢数据。
- **演示任务**：`2026年度能源利用状况报告`（guided）、`2026年度能源利用状况报告2`（document）。
- **报告完整结构**（与附件2 一致，非简化骨架）：
  - **10 个正文部分**：用能单位基本情况 / 能源消费情况 / 能源利用效率 / 主要用能环节与设备 / 节能措施与节能量 / 碳排放情况 / 可再生能源利用 / 节能法规执行情况 / 节能目标完成情况 / 下一年度节能计划
  - **11 张附件表**（工业场景，取自模板 PT-012 sections）：表1 基本情况、表2 能源消费结构、表3 结构附表、表4 单位产品综合能耗、表5 其他单位产品、表6 数据中心能效、表7 节能目标进度、表8 节能改造项目、表26 碳排放情况、表27 新能源及可再生能源、表28 节能工作自查
  - 表格列与行来自模板定义，演示数据由 `ANNEX_DEMO_CELLS` / `ANNEX_DEMO_ROWS` 补齐；列多时横向滚动、状态列吸附右侧
- **关键实现**：`isDocumentMode` / `docSections`（computed，由 `templateSections` + `BODY_DEMO` 动态生成）/ `docStats` / `focusDocItem()` / `confirmDocItem()` / `docFullCheck()` / `docFinalize()`。
