## 0. 职责边界（重要）

### 0.1 两类数据的两种来源

本模块管理的数据分为**两类**，来源与维护方式不同：

| 类型 | 典型示例 | 创建入口 | 本模块权限 |
|---|---|---|---|
| **政策文件** | 发改环资〔2025〕910号、京环发〔2026〕7号、欧盟 CBAM 条例、认监委公告 | **政策采集与发布**（其他模块）| **只读**（同步）|
| **标准** | GB/T 36132-2025、ISO 14067、DB11/T 1781、T/CAQP 026、GHG Protocol、EF 3.0 方法 | **本模块** | **可创建/编辑** |

### 0.2 为什么这样划分

- **政策文件**：平台其他模块已建「政策采集与发布」，具备原文上传、元信息登记、发布审批能力 → **避免双主入口**，本模块只同步
- **标准**：其他模块不采集标准（标准由标准化机构发布，非"政策"）→ **本模块必须自建**
- **统一管理**：两类数据在本模块统一建模、统一结构化解析、统一输出配置包，供下游消费

### 0.3 解析能力来自 Skill 管理

**标准/规范的结构化解析不在本模块硬编码**，而是由「运维管理 → Skill 管理」中定义的 **Skill（技能）** 驱动：

| 概念 | 说明 |
|---|---|
| **Skill** | 一个可复用的解析技能，含：提示词模板（prompt）+ 因子匹配规则（factorPriority）+ 触发阶段（phase）+ 关联知识库（knowledgeBase）+ 绑定标准（standardCode）|
| **Skill 驱动解析** | 本模块解析标准时，**选择对应 Skill**，由 Skill 的提示词模板与规则驱动大模型完成提取 |
| **差异化适配** | 不同场景/不同标准类型，加载不同 Skill（如「GB/T 36132 解析技能」「ISO 14067 解析技能」「零碳园区指标解析技能」）|

**为什么用 Skill 驱动**：

- **标准会变**：新标准、标准升版 → 只需新增/调整 Skill，不改代码
- **场景有差异**：同一标准在不同场景下关注的参数不同 → Skill 可按场景定制
- **能力可复用**：一个 Skill 可服务多个标准（同族标准）
- **可调优**：提示词模板与匹配规则可在线编辑、预览、重置

## 1. 模块定位

### 1.1 解决的问题

碳核算的前提是**标准**：不同场景（产品/组织/园区/工厂）适用不同标准，各标准的核算边界、参数、指标、权重、评分规则、数据要求、公式引用差异显著。若标准以文档形式散落，则：

- 各场景需重复解读标准，口径易冲突
- 标准更新后，公式与模板无法同步
- 核算结果无法回溯到"依据哪条标准、哪个版本"

政策标准库将**政策文件（同步）与标准（自建）**统一转为"结构化配置"，作为平台标准配置驱动的**加工端**。

### 1.2 被谁依赖

| 消费方 | 消费内容 |
|---|---|
| **核算公式库** | 标准的「核算公式」映射、参数定义 |
| **平台模板库** | 标准的「指标体系」「权重」「评分规则」「边界模板」「数据模板」「报告模板」 |
| **排放因子库** | 标准要求的因子类别与适用条件 |
| 8 个业务场景智能体 | 标准清单、结构化配置包、版本号（用于结果标注依据） |

### 1.3 输出物

```
政策文件（同步） + 标准（自建）
    │ 条款切分
    ↓
标准条款（Clause，带条款号）
    │ 结构化解析（AI 辅助 + 人工确认）
    ↓
结构化配置包（StructuredConfig）
    ├ 参数（Param）        键 / 值 / 单位 / 条款溯源
    ├ 指标（Indicator）    名称 / 类别 / 基本要求 / 目标要求 / 统计口径 / 权重 / 星级规则
    ├ 数据要求（DataReq）  类别 / 指标 / 数据源
    └ 公式映射（Formula）  因子类别 / 核算公式
    │
    ├──→ 核算公式库（消费「公式映射」）
    └──→ 平台模板库（消费「指标 / 权重 / 评分规则 / 边界」）
```

## 2. 数据模型

### 2.1 标准（Standard）

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `id` | string | 是 | 主键（本模块内部 ID）|
| **`sourceSystem`** | enum | 是 | **来源**：`policy-center`（政策同步）/ `local`（本模块创建）|
| **`sourceId`** | string | 否 | 来源政策 ID（`policy-center` 时有值；`local` 时为空）|
| **`syncTime`** | datetime | 否 | 最近同步时间（仅 `policy-center`）|
| **`syncStatus`** | enum | 否 | 已同步 / 待更新 / 来源已废止（仅 `policy-center`）|
| **`code`** | string | **否** | **编号 / 文号**（标准填 `GB/T 36132-2025`，政策填 `京环发〔2026〕7号`，无编号填 `—`）**非必填**：政策/规范类常无正式编号 |
| `name` | string | 是 | 标准/政策名称 |
| `type` | enum | 是 | 国家标准 / 行业标准 / 地方标准 / 团体标准 / 国际标准 / 规范指南 / **政策文件** |
| `scenarios` | array | 否 | **业务场景**（多选：产品碳足迹 / 组织碳核算 / 园区碳核算 / 绿色工厂 / 零碳工厂 / 北京碳市场 / 智慧报告）|
| `issuer` | string | 否 | 发布机构 |
| **`year`** | number | **否** | 发布年份（**非必填**：部分政策无明确年份）|
| **`version`** | string | **否** | **系统配置版本**（`V1`/`V2`/`V3`）：本平台对该标准配置的修订次数。**注意区分两种版本**：① 文件本身的多个版本 → 用 `code` 区分（编号含年份，`GB/T 24067-2018` 与 `GB/T 24067-2024` 是**两条独立记录**）；② 同一文件的多次配置修订 → 用 `version` 区分（V1→V2→V3，**多版配置并存**）。与 `code` 组合唯一 |
| `publishStatus` | enum | 是 | **现行 / 废止**（与页面一致）|
| **`summary`** | text | 否 | **简介**（标准/政策内容概述，≤500 字）|
| `parseStatus` | enum | 是 | **未解析 / 解析中 / 解析失败**（技术状态）|
| **`configStatus`** | enum | 是 | **待确认 / 已生效**（业务状态：解析完成后为「待确认」，人工确认后为「已生效」）|
| **`parseSkillId`** | string | 否 | **解析所用 Skill ID**（来自 Skill 管理）|
| **`parseSkillName`** | string | 否 | Skill 名称（冗余展示）|
| **`level`** | string | 否 | **层级**（预留字段，待上游「政策采集与发布」增加后同步）|
| **`node`** | string | 否 | **所属节点**（预留字段，同上）|
| `effectiveDate` | date | 否 | 生效日期 |
| `fileUrl` | string | 否 | 原文附件地址 |
| `createdAt` / `updatedAt` | datetime | 是 | 创建/更新时间 |

**约束**：

| 约束 | 说明 |
|---|---|
| `sourceSystem = policy-center` | `sourceId` 必填；`code`/`name`/`type`/`issuer`/`year`/`fileUrl`/`publishStatus` **只读**（由上游同步覆盖）|
| `sourceSystem = local` | 全部字段**可编辑**；`sourceId` 为空 |
| **类型互斥** | `type = 政策文件` 时，`sourceSystem` 必须为 `policy-center`（禁止本地创建政策文件）|
| **唯一性** | `sourceSystem + sourceId` 唯一（同步去重）；`code + version` 唯一 |
| **可加载条件** | `publishStatus = 现行` 且 `parseStatus = 解析完成` 且 `configStatus = 已生效` |

### 3.2 编辑表单（两类数据共用）

政策文件与标准**共用同一套字段与编辑表单**（「编辑核算标准」弹窗），字段清单如下：

| 字段 | 控件 | 必填 | 说明 |
|---|---|---|---|
| **编号 / 文号** | 输入框 | **否** | 标准填 `GB/T 24867-2024`；政策填 `京环发〔2026〕7号`；无编号可留空 |
| 名称 | 输入框 | ✅ | 如"欧盟碳边境调节机制（CBAM）嵌入式排放核算" |
| 标准类型 | 下拉 | ✅ | 国家/行业/地方/团体/国际/规范指南/**政策文件** |
| **业务场景** | 多选 | 否 | 产品碳足迹 / 组织碳核算 / 园区碳核算 / 绿色工厂 / 零碳工厂 / 北京碳市场 / 智慧报告 |
| 发布机构 | 输入框 | 否 | 如"欧盟委员会"、"国家市场监督管理总局" |
| **发布年份** | 年份选择 | **否** | 如 2024；无明确年份可留空 |
| 状态 | 单选 | ✅ | **现行 / 废止** |
| **版本** | 输入框 | **否** | 标准填 `v1.0`；政策通常留空 |
| 简介 | 多行文本 | 否 | ≤500 字，概述内容与主要指标 |

**通用性说明**：本表单覆盖**标准**（GB/T、ISO、DB11/T、T/CAQP 等）与**政策文件**（通知、办法、意见、公告、附件）两类，通过「编号/文号」非必填、年份与版本可空来适配"政策常无编号/年份/版本"的现实情况。**已移除原「适用范围」字段**——该字段当前填写内容为场景简称，与「业务场景」重复；标准的行业适用范围可写入「简介」。

**字段可编辑性（按来源区分）**：

| 字段 | `local`（自建）| `policy-center`（同步）|
|---|---|---|
| 编号/文号 / 名称 / 类型 / 发布机构 / 发布年份 / 简介 | ✅ 可编辑 | 🔒 只读（同步覆盖）|
| 业务场景 | ✅ 可编辑 | ✅ **可编辑**（本模块补充的关联信息）|
| 状态（现行/废止）| ✅ 可编辑 | 🔒 只读（由上游驱动）|
| 版本 | ✅ 可编辑 | 🔒 只读 |

### 3.3 创建入口规则（关键）

| 用户操作 | 系统行为 |
|---|---|
| 点击「+ 新增标准」 | 弹出选择：**标准类型**（国家/行业/地方/团体/国际/规范指南）→ **不含"政策文件"** |
| 若用户尝试创建"政策文件" | 拦截并提示："政策文件请到「政策采集与发布」创建，本模块将自动同步" |
| 编辑 `policy-center` 来源的记录 | 基础信息字段置灰，仅「业务场景」「结构化配置」可编辑 |
| 删除 `policy-center` 来源的记录 | **不允许**（提示"请到「政策采集与发布」删除，本模块将自动同步状态"）|

### 3.4 存量与增量策略

平台存在**存量数据**（上线时已录入）与**增量数据**（后续新增）两种情形，处理方式如下：

| 数据 | 来源标识 | 创建方式 | 说明 |
|---|---|---|---|
| **存量标准** | `local` | 本模块创建 | 上线时已录入的国家/行业/地方/团体/国际标准 |
| **存量政策文件** | `local` | 本模块创建 | 上线时已录入的政策（如 CBAM），上游尚未录入 |
| **增量标准** | `local` | 本模块创建 | 后续新增标准仍在本模块创建 |
| **增量政策文件** | `policy-center` | 从上游同步 | 上游录入并发布后，本模块同步 |

**存量政策文件的迁移路径（可选）**：

```
1. 上游「政策采集与发布」补录该政策（如 CBAM）
2. 本模块在列表页对该记录点击「关联同步」
3. 系统匹配上游记录（按文号/名称）→ 绑定 sourceId
4. sourceSystem 由 local 改为 policy-center
5. 仅覆盖上游字段（编号/名称/机构/年份/简介/状态），
   保留本模块已维护的「业务场景/结构化配置」
```

**迁移保护**：
- 迁移前提示"将转为同步管理，基础信息后续以上游为准"
- 迁移后不可回退为 local（避免来源混乱）
- 迁移记录写入审计日志

### 3.5 同步机制（仅政策文件）

#### 触发方式

| 方式 | 说明 |
|---|---|
| **定时同步** | 每日 02:00 增量（拉取 `updatedAt > lastSyncTime`）|
| **手动同步** | 页面「同步」按钮 |
| **单条同步** | 详情页「重新同步」 |

#### 冲突处理

| 场景 | 处理 |
|---|---|
| 来源内容更新（同版本）| 更新只读字段 + 标记「待更新」，提示"原文已变更，建议重新解析" |
| 来源升版 | 新建 `StandardVersion` 快照，**保留旧版本结构化配置** |
| 来源废止 | 标记「已废止」，场景侧只读 + 提示 |
| 来源删除 | **保留本模块记录** + 标记"来源已删除"，不自动删（保护加工成果）|
| 同步 vs 加工成果 | **同步不覆盖**参数/指标/规则 |

### 3.6 状态流转

#### ① 解析状态（技术状态，`parseStatus`）

```
未解析 ──触发解析──→ 解析中 ──成功──→ 解析完成（自动入库，configStatus = 待确认）
                        │
                        └──失败──→ 解析失败（可重试）
```

**关键**：解析成功后**自动入库**（生成结构化配置），但 `configStatus` 为「**待确认**」，不立即可用。

#### ② 配置状态（业务状态，`configStatus`）

```
待确认 ──人工确认──→ 已生效 ──人工撤回──→ 待确认
```

| 状态 | 含义 | 能否被场景加载 |
|---|---|---|
| **待确认** | AI 解析完成，等待人工核对 | ✗ 不可加载 |
| **已生效** | 人工逐项确认无误 | ✅ 可加载 |

**确认粒度**：支持**逐项确认**（参数/指标/规则分别确认）或**整体确认**（一次确认全部）。

#### ③ 发布状态（`publishStatus`，来源侧）

| 来源 | 流转 |
|---|---|
| policy-center | 现行 → 废止（由上游驱动）|
| local | 草稿 → 现行 → 废止（本模块操作，**无审核环节**）|

#### ④ 三者关系

```
解析状态（parseStatus）      → 决定「有没有结构化配置」
配置状态（configStatus）     → 决定「配置能不能用」
发布状态（publishStatus）    → 决定「标准本身是否有效」

场景加载条件（三者同时满足）：
  parseStatus = 解析完成
  且 configStatus = 已生效
  且 publishStatus = 现行
```

### 3.7 权限

| 角色 | 查看 | 同步 | 创建/编辑（local）| 解析 | 导出 |
|---|---|---|---|---|---|
| 平台运维 | ✓ | ✓ | ✓ | ✓ | ✓ |
| 场景使用者 | ✓ | ✗ | ✗ | ✗ | ✗ |
| 审计员 | ✓ | ✗ | ✗ | ✗ | ✓ |

**约束**：`policy-center` 来源的基础信息**任何角色不可编辑**。

### 6.5 同步更新对现有结构的影响与处理

政策文件内容随上游更新，**不会破坏数据结构**（同表建模 + 新增字段，向后兼容），但会影响下游引用。影响面与处理规则如下：

#### ① 影响面分析

| 影响对象 | 影响 | 严重度 | 处理策略 |
|---|---|---|---|
| **数据结构** | 无（同表 + `sourceSystem` 区分，字段只增不改）| 无 | 向后兼容 |
| **标准记录** | 只读字段被覆盖（编号/名称/机构/年份/简介/状态）| 低 | 版本快照 |
| **结构化配置** | 内容变更后旧解析结果可能失效 | 中 | 标记「待重新解析」，**不自动覆盖** |
| **下游公式库** | 引用的标准条款/公式变了 | 高 | 版本变更通知 → 人工确认 |
| **下游模板库** | 指标/权重/评分规则变了 | 高 | 同上 |
| **排放因子库** | 因子类别/适用条件变了 | 中 | 同上 |
| **场景配置** | 场景配置时记录的版本号已过时 | 中 | 提示"标准已更新" |
| **已核算结果** | 结果依据旧版本标准 | 高 | **结果冻结**（记录版本号，不自动重算）|

#### ② 四条核心原则

| 原则 | 说明 |
|---|---|
| **不破坏** | 同步只更新只读字段，**不动**本模块加工成果（结构化配置）|
| **留快照** | 每次内容变更生成 `StandardVersion` 快照，可回溯 |
| **不自动传播** | 下游（公式/模板/因子/场景）**不自动改**，只接收通知并人工确认 |
| **结果冻结** | 已核算结果绑定版本号，标准更新后**不自动重算** |

#### ③ 具体处理规则

| 场景 | 处理 |
|---|---|
| 政策内容更新（同版本）| 更新只读字段 → `syncStatus = 待更新` → 提示"原文已变更，建议重新解析"（**不自动解析**）|
| 政策升版（新版本）| 新建 `StandardVersion` → 旧版本结构化配置**保留** → 下游收到"版本变更"通知 |
| 政策废止 | `publishStatus = 废止` → 场景侧只读 + 提示 → **已核算结果不受影响** |
| 本模块已改结构化配置 + 来源再更新 | **保留**本模块配置，仅更新只读字段，`syncStatus = 待更新` |
| 来源删除政策 | 保留记录 + 标记"来源已删除"，不删（保护加工成果）|

#### ④ 已核算结果的保护机制

```
核算结果记录（由场景侧维护）：
  · standardId          使用哪个标准
  · standardVersion     核算时使用的版本
  · parseSkillId        解析所用 Skill
  · parsedAt            解析时间

标准更新后：
  · 已核算结果保持原版本，不重算
  · 新核算任务使用新版本
  · 支持"按版本对比结果差异"（如 v1.0 核算 vs v1.1 核算）
```

#### ⑤ 下游通知机制

| 通知方式 | 说明 |
|---|---|
| **接口查询** | 下游调用 `GET /api/standards/{id}/version-alert?configuredVersion=v1.0` → 返回是否需提醒 |
| **列表标记** | 公式库/模板库列表页，引用了过时标准的行显示 ⚠ 图标 |
| **主动推送（可选）** | Webhook / MQ 推送标准变更事件，下游异步处理 |

**设计取舍**：**不自动同步下游**。原因：
- 公式/模板变更影响核算结果正确性，必须人工确认
- 自动传播会导致"标准一改，历史配置全变"，难以追溯
- 平台采用"提示 + 人工确认"模式，保证每次变更可审计

## 9. 补充设计

### 9.1 业务流程（端到端）

#### 流程 A：政策文件同步入库

```
上游发布政策
  → 定时（每日 02:00）/ 手动同步
  → 生成标准记录（sourceSystem = policy-center，publishStatus = 现行）
  → parseStatus = 未解析
  → 触发解析 → 选择 Skill → 解析中
  → 解析完成（自动入库，configStatus = 待确认）
  → 人工逐项核对 → 全部确认（configStatus = 已生效）
  → 可被场景加载
```

#### 流程 B：标准本地创建

```
点击「+ 新增标准」（选择标准类型，不含政策文件）
  → 填写 9 项表单 → 保存（publishStatus = 草稿）
  → 上传原文（PDF/Word）→ 发布（publishStatus = 现行）
  → 触发解析 → 选择 Skill → 解析完成（configStatus = 待确认）
  → 人工确认（configStatus = 已生效）
```

#### 流程 C：存量政策文件迁移

```
上游补录该政策
  → 本模块对该记录点击「关联同步」
  → 按文号/名称匹配上游记录 → 绑定 sourceId
  → sourceSystem: local → policy-center
  → 仅覆盖上游字段（编号/名称/机构/年份/简介/状态）
  → 保留本模块已维护的「业务场景/结构化配置」
```

### 9.4 典型示例（以 GB/T 36132-2025 为例）

#### ① 创建（local）

| 字段 | 值 |
|---|---|
| 编号/文号 | GB/T 36132-2025 |
| 名称 | 绿色工厂评价通则 |
| 标准类型 | 国家标准 |
| 业务场景 | [绿色工厂] |
| 发布机构 | 国家市场监督管理总局 |
| 发布年份 | 2025 |
| 状态 | 现行 |
| 简介 | 规定绿色工厂评价的五化 14 项指标与评分规则 |

→ 上传原文 PDF（约 60 页）→ 发布（`publishStatus = 现行`）

#### ② 解析（Skill 驱动）

```
点击「解析」→ 按 standardCode 匹配到「GB/T 36132 解析技能」
→ 解析中（约 2 分钟）
→ 解析完成，自动入库：
   · 参数 28 项（含引领值/基准值）
   · 指标 14 项（5 个一级 × 14 个二级）
   · 权重 14 项（合计 100%）
   · 评分规则 14 条（引领值满分 / 基准值零分 / 区间线性插值）
   · 数据要求 26 条
   · 公式映射 8 条
→ configStatus = 待确认
```

#### ③ 人工确认

```
逐项核对参数/指标/权重（对照原文条款）
→ 发现「能源消耗强度」基准值需调整（0.0040 → 0.0042）
→ 修改后点击「全部确认」
→ configStatus = 已生效
```

#### ④ 下游消费

```
平台模板库：拉取指标/权重/评分规则 → 生成"绿色工厂评价模板"
核算公式库：拉取公式映射 → 生成 8 条核算公式
绿色工厂场景：加载配置包 → 进入「标准规则适配」阶段
```

### 9.5 异常处理

| 异常 | 处理 |
|---|---|
| **同步失败**（上游不可用）| 记录失败原因，自动重试 3 次（间隔 5min），仍失败则告警；**保留上次成功数据**，不破坏现有记录 |
| **OCR 失败**（扫描件模糊）| 标记"OCR 质量差"，提示人工录入或更换清晰原文 |
| **解析失败**（模型超时/输出不合规）| 记录失败原因，支持重试；连续失败 3 次提示"更换 Skill" |
| **解析结果为空** | 标记"解析无结果"，提示"检查原文格式或更换 Skill" |
| **人工确认发现错误** | 可修改任意字段，修改记录留痕（旧值 → 新值）|
| **标准被引用后要废止** | 提示引用范围（X 公式 / Y 模板 / Z 场景），确认后废止 |
| **上游政策被删除** | 保留本模块记录 + 标记"来源已删除"，不自动删 |
