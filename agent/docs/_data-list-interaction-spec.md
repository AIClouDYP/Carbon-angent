# 数据清单统一交互规范（平台级共性）

> 适用范围：碳核算智能体 8 个业务场景中「数据清单 / 排放源清单 / 参数清单」类功能
> 版本：v1.0（2026-10-26）
> 状态：已落地（组织碳核算、北京碳市场、园区碳核算、绿色工厂）

---

## 1. 设计原则

数据清单是各场景的核心工作区。同一类操作（点击一行查看某条数据的详情）在 8 个场景中**必须行为一致**，避免用户在不同场景间切换时重新学习。

统一遵循：**对话引导为主，结构化抽屉为辅**。

| 层次 | 载体 | 承担 |
|---|---|---|
| 主路径 | **左侧对话引导** | 摘要查看、可执行操作、留痕 |
| 补充 | **右侧抽屉** | 完整参数链、凭证预览、变更历史（引导放不下的内容）|

**理由**：
1. 产品定位是「AI 对话驱动的碳核算智能体」，不是「碳数据填报系统」
2. 核算过程需可审计（谁在何时确认了什么）——对话天然留痕，抽屉不留痕
3. 高频操作（确认、改值）在对话里比「开抽屉→找字段→改→保存→关闭」快
4. 抽屉在 400~440px 宽度内无法承载全部信息，强行使用会导致内容挤压

## 2. 交互契约

```
用户点击数据行
      │
      ├─→ ① 左侧推送「数据卡片」（不自动打开抽屉）
      │      · 数据名称 / 所属范围
      │      · 主指标值（排放量 / 消耗量）
      │      · 数据状态（已确认 / 待确认 / 缺失）
      │      · 提示语（引导下一步动作）
      │
      ├─→ ② 卡片下方给出建议按钮
      │      · [查看完整溯源]  · [确认此数据]
      │
      └─→ ③ 点击「查看完整溯源」
             └─→ 右侧抽屉打开（仅此时出现）
                    · 完整参数链（活动数据 / 排放因子 / 计算过程）
                    · 凭证预览
                    · 变更历史
```

**禁止**：
- ❌ 点击行直接打开抽屉（打断清单浏览）
- ❌ 点击行同时推引导 + 开抽屉（信息重复、互相遮挡）
- ❌ 抽屉里重复展示卡片已有的摘要（名称/排放量/状态）

## 3. 数据卡片内容规范

| 区块 | 内容 | 是否必填 |
|---|---|---|
| 标题 | `【数据溯源】{数据名称}` | 必填 |
| 所属范围 | `{范围} · {类别}` | 必填 |
| 主指标值 | `{排放量} tCO₂e`（若有）| 有则显示 |
| 数据状态 | 已确认（绿）/ 待确认（橙）/ 缺失数据（红）| 必填 |
| 提示语 | 说明如何查看完整溯源 | 必填 |
| 建议按钮 | `查看完整溯源`、`确认此数据` | 必填 |

**视觉规范**（与阶段2/3 数据卡片一致）：
- 卡片容器：`padding:10px 12px; background:rgba(0,103,254,0.04); border-radius:8px; border-left:3px solid #0067FE`
- 主指标值：`color:#0067FE; font-size:15px; font-weight:700`
- 状态色：已确认 `#52C41A` / 待确认 `#E6A23C` / 缺失 `#F56C6C`

## 4. 抽屉职责

抽屉**只放引导卡片放不下的内容**：

| 页签 | 内容 |
|---|---|
| 计算参数 | 活动数据、排放因子、计算过程（完整链路）|
| 溯源凭证 | 凭证名称、页码、预览、SHA-256 签名 |
| 变更历史 | 时间轴（谁 / 何时 / 旧值 → 新值 / 原因）|

**抽屉不展示**：数据名称、排放量、状态（卡片已有）

## 5. 代码接口约定

各场景实现须提供以下方法（命名统一，便于后续抽取为公共 mixin）：

| 方法 / 属性 | 职责 |
|---|---|
| `openTrace(row)` | 点击数据行的统一入口：记录 `traceRow`，推引导，**不打开抽屉** |
| `pushTraceGuide(row)` | 生成并推送数据卡片（含建议按钮）|
| `traceRow` | 当前聚焦的数据行 |
| `traceDrawer` | 抽屉开关（`openTrace` 中置 `false`）|
| `handleCommonIntent(q)` 中识别「溯源」 | 输入含「溯源」→ 打开抽屉 |

**意图识别**：
```js
if (lower.indexOf('溯源') > -1 && (lower.indexOf('查看') > -1 || lower.indexOf('完整') > -1 || lower.indexOf('明细') > -1)) {
  if (this.traceRow) { this.traceDrawer = true }
  return true
}
```

## 7. 实现载体与后续演进

### 7.1 公共 mixin（已完成）

`src/pages/zcip/common/traceGuideMixin.js` 提供：

| 方法 | 说明 |
|---|---|
| `pushTraceGuide(row, options)` | 推数据卡片（含建议按钮）；`options` 可覆盖标题/建议/附加 HTML |
| `handleTraceIntent(q)` | 识别「溯源」意图，打开抽屉；返回 `true` 表示已处理 |

**使用方式**（3 个场景已接入）：

```js
import traceGuideMixin from '../../common/traceGuideMixin'

export default {
  mixins: [traceGuideMixin, agentCoreMixin, agentChatMixin],
  methods: {
    openTrace(row) {
      this.traceRow = row
      this.traceDrawer = false
      this.pushTraceGuide(row)
    }
  }
}
```

意图分支（各场景 `handleCommonIntent` 开头）：

```js
if (this.handleTraceIntent(lower)) return true
```

### 7.2 建议按钮动作（已完成）

mixin 提供 `confirmTraceRow(row)`，并已接入 `handleTraceIntent`：

| 输入 | 行为 |
|---|---|
| 含「确认」+ 有 `traceRow` | 调用 `confirmTraceRow` |
| 数据完整 | `$set(row, 'confirmed', true)` → 提示「已确认，将参与后续计算」|
| 已确认过 | 提示「此前已确认，无需重复操作」|
| 缺失数据（`hasData: false`）| 提示「缺失数据，无法确认，请先补充」|

数据行状态标签（3 个场景已加）：
- `!r.hasData` → 「待补录」（灰）
- `r.confirmed` → 「已确认」（绿）
