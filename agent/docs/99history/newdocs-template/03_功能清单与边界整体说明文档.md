## 二、 系统核心边界与防撕扯声明

> *【编写指引】明确项目的“不做什么”与“责任边界”，避免后期因无限蔓延的需求导致项目无法结项。*

### 2.1 算法确定性与大模型边界（防幻觉红线）
* **红线规定**：系统内所有涉及能耗折标（tce）、碳排放量（tCO₂）、加总平衡等法律责任指标，**100% 由代码物理公式与规则引擎计算，并固化为只读**。
* **大模型权限**：大模型仅被授权作为“智能副驾驶”，负责自然语言问答、缺项引导提示、文字叙述润色。大模型**严禁改动任何数字**。

### 2.2 平台功能与底层物联底座边界
* **平台建设范围**：专注于业务场景编排、口径适配、指标核算、合规校验、报告产出与全流程溯源。
* **外部数据边界**：现场物理硬件表计的安装与调试、厂级 SCADA 系统的搭建、园区 IoT 传感器的物理布线属于外部基础设施或统一数据底座，本平台通过标准化接口或离线导入协议只读消费。

### 2.3 原型阶段与生产上线技术边界
* **数字存证边界**：当前前端原型采用纯前端 SHA-256 哈希算法生成防伪内容指纹；生产环境部署时将平滑替换为企业 CA 机构电子签章与服务端国密加密网关。
* **数据持久化边界**：原型阶段状态持久化采用浏览器本地命名空间隔离缓存，生产上线后无缝映射至微服务 RESTful API 与分布式关系数据库。

### 2.4 责任认定与企业免责边界
* **异常工况责任**：若系统检出极值异动（如由于停产检修导致月用电量暴跌 60%），系统仅负责标黄拦截；由企业填报人主动选择“生产工况变化”并人工输入豁免说明，该说明将作为法律证据随报告一同存档，证明非系统计算漏洞。
