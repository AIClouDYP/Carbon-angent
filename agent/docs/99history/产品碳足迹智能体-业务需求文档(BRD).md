## 一、文档概述

### 1.1 编写目的

本文档定义「产品碳足迹核算智能体」（以下简称"碳亦管·碳足迹智能体"）的核心业务需求，包括业务背景、目标、用户角色、核心业务流程、关键业务规则和非功能性需求。旨在为后续功能需求文档(FRD)、系统设计和开发测试提供明确的业务基线。

### 1.2 适用范围

本期碳亦管平台包含2个碳核算智能体：**产品碳足迹智能体**（本文档主体）和**组织碳核算智能体**（姊妹智能体）。本文档适用于产品碳足迹智能体的全部业务功能，涵盖从智能体入口到核算报告输出的完整产品线。组织碳核算智能体的详细需求见其独立需求文档，本文档仅在第六章定义两者之间的交互关系。能碳报告智能体、能碳诊断智能体、能源优化调度智能体等其他智能体属于远期规划，本期不涉及。

## 二、业务背景与问题定义

### 2.1 业务背景

在全球"双碳"目标驱动下，产品碳足迹（Product Carbon Footprint, PCF）核算已成为企业出口合规、绿色供应链准入、碳标签认证的刚性需求。欧盟碳边境调节机制（CBAM）、欧盟电池法规(EU 2023/1542)、中国GB/T 24067-2024均要求企业提供经核证的产品碳足迹声明。

然而，当前产品碳足迹核算面临以下痛点：

| 痛点 | 具体表现 | 业务影响 |
| --- | --- | --- |
| **流程复杂** | 碳足迹核算涉及ISO 14044九阶段LCA方法论，非专业用户难以驾驭 | 80%企业需外聘第三方LCA咨询，单次核算周期2~6个月，费用5~20万 |
| **数据采集难** | BOM/能耗/运输数据散落在ERP/MES/TMS/IoT多个系统，手工汇总易遗漏 | 数据完整性不足导致报告退回，平均补采次数3~5轮 |
| **因子匹配乱** | 排放因子版本多、地域覆盖差异大、更新频繁，人工选取易出错 | 因子选用不当导致计算偏差30%以上，严重者报告被拒 |
| **质量管控弱** | 缺乏系统化的完整性/一致性/DQR校验机制 | 报告可信度存疑，第三方核查失败率居高 |
| **响应速度慢** | 供应链上下游碳数据联动依赖邮件/问卷，响应周期长 | 无法满足"72小时出初版报告"的市场诉求 |

### 2.2 目标定位

碳足迹智能体的核心定位是：**将产品碳足迹核算从"专家手工操作"转化为"AI引导的自助化标准流程"**，让碳管理师和业务人员能在AI智能体引导下完成从数据采集到报告输出的全流程，无需深度掌握LCA方法论。

### 2.3 业务目标

| 目标编号 | 目标描述 | 量化指标 | 优先级 |
| --- | --- | --- | --- |
| BG-01 | **降低核算门槛** | 非LCA专业人员可在智能体引导下独立完成核算，无需第三方辅导 | P0 |
| BG-02 | **缩短核算周期** | 从创建任务到输出初版报告≤72小时（含数据采集），全流程≤7个工作日 | P0 |
| BG-03 | **提升数据质量** | 核算报告通过第三方核查的成功率≥90%（当前行业平均约65%） | P0 |
| BG-04 | **多标准合规** | 同时满足ISO 14067/PAS 2050/GB/T 24067/EPD®四大标准的数据质量要求 | P1 |
| BG-05 | **供应链联动** | 核心供应商碳数据回收率≥80%，问卷响应周期≤5个工作日 | P2 |

## 四、核心业务流程

### 4.1 九阶段核算总流程

产品碳足迹核算遵循ISO 14044 LCA方法论，智能体将九阶段转化为可交互的标准化流程：

```
 ┌─────────────┐   ┌─────────────┐   ┌─────────────┐   ┌──────────────┐   ┌──────────────┐
 │ Stage 1     │→ │ Stage 2     │→ │ Stage 3     │→ │ Stage 4      │→ │ Stage 5      │
 │ 目标与范围  │   │ 功能单位    │   │ 系统边界    │   │ 数据采集     │   │ 因子匹配     │
 │ 定义        │   │ 与基准      │   │ 划定        │   │              │   │              │
 └─────────────┘   └─────────────┘   └─────────────┘   └──────────────┘   └──────────────┘
       ↓                 ↓                 ↓                 ↓                  ↓
 ┌─────────────┐   ┌─────────────┐   ┌─────────────┐   ┌──────────────┐
 │ Stage 6     │→ │ Stage 7     │→ │ Stage 8     │→ │ Stage 9      │
 │ 数据校验    │   │ 碳足迹计算  │   │ 结果解释    │   │ 报告生成     │
 │ (四项串行)  │   │              │   │              │   │              │
 └─────────────┘   └─────────────┘   └─────────────┘   └──────────────┘
```

**关键业务规则**：

- **串行推进**：每个阶段完成后才能进入下一个阶段，不可跳跃
- **阻断式校验**：Stage 6数据校验中，四项校验（完整性→一致性→趋势→DQR）按序执行，任何一项未通过即阻断后续
- **人机协同**：每个阶段均有AI智能体引导，但关键决策点（如边界划定、因子确认、异常处理）需人工确认
- **可回退**：任意阶段可回退到上一个阶段修正数据，但不跳过校验

### 4.2 核心业务子流程

#### 4.2.1 任务创建与产品模型配置（Stage 1-3）

```
用户输入产品名称 → AI识别产品类别 → 推荐产品模型模板 → 用户确认/修改
      ↓
AI辅助设定功能单位 → 推荐核算标准组合 → 用户选择标准
      ↓
AI自动生成系统边界草案 → 用户调整边界(含/不含阶段) → AI校验边界完整性 → 锁定边界
```

**输入**：产品名称、型号、组织边界、核算周期  
**输出**：核算任务配置（产品模型、功能单位、系统边界、适用标准）  
**触发**：碳管理师在任务列表页点击「创建核算任务」  
**预期行为**：AI在3步对话内完成Stage 1-3配置，给出系统边界预览图供确认

#### 4.2.2 数据采集与因子匹配（Stage 4-5）

```
AI列出排放源清单 → 按工序/阶段分组展示 → 用户逐项填报或批量导入
      ↓
自动/IoT拉取能耗数据 → ERP/MES同步BOM数据 → 供应商问卷回收上游数据
      ↓
AI自动匹配排放因子 → 标注匹配置信度 → 用户确认/更换因子 → 因子库锁定
```

**输入**：活动数据（手工填报/Excel导入/IoT自动/ERP同步/供应商问卷）  
**输出**：已匹配的排放源清单（每项含：活动数据值+单位+排放因子+因子版本+数据来源标注）  
**触发**：任务状态进入`DATA_COLLECTING`  
**预期行为**：AI实时显示填写率进度条，自动匹配因子置信度≥85%的项直接锁定，<85%的弹出确认卡片

#### 4.2.3 数据校验（Stage 6）— 四项串行阻断

```
完整性校验 → 一致性校验 → 趋势校验 → DQR数据质量校验
     ↓             ↓            ↓            ↓
  6条规则        6条规则       6条规则      12条规则(双轨)
  🔴4/🟡2       🔴1/🟠3/🟡2  🔴1/🟠1/🟡4  🔴2/🟠4/🟡6
```

**输入**：已匹配的排放源数据集  
**输出**：校验结果（通过/异常卡片列表），所有卡片处理为「已处理」后放行  
**触发**：任务状态进入`GOVERNANCE`  
**业务规则**：详见《阶段6-数据校验规则详解 v2.1》，核心要点：
  - 三级严重程度：🔴阻断→🟠阻断确认→🟡警告
  - 六种处理方式：补充数据/确认使用/确认正常/接受评分/更新因子/忽略
  - 所有异常卡片最终必须处理为「已处理」才能进入Stage 7

#### 4.2.4 碳足迹计算与结果解释（Stage 7-8）

```
逐源计算: emission = activity_value × factor_value → 按范围(Scope1/2/3)汇总
     ↓
按生命周期阶段汇总 → 生成瀑布图/占比图/贡献度排名
     ↓
AI识别热点排放源 → 生成减排建议 → 对标同类产品/历史数据
```

**输入**：校验通过的排放源数据集  
**输出**：碳足迹总量(kgCO2e)、范围分解、阶段分解、不确定度范围、热点分析  
**触发**：Stage 6全部校验通过  
**预期行为**：计算耗时≤30秒，AI自动生成热点识别和减排建议优先级清单

#### 4.2.5 报告生成与签发（Stage 9）

```
选择报告模板(ISO/PAS/GB/EPD) → AI编排报告章节 → 自动填充数据与图表
     ↓
碳管理师审核报告 → 专家审核员复核方法论与DQR声明 → 签发
     ↓
导出PDF/Word/Excel → 存入报告库 → 可推送至供应链/认证机构
```

**输入**：核算结果、校验记录、因子来源元数据  
**输出**：符合选定标准格式的碳足迹核算报告  
**触发**：Stage 8结果解释确认  
**预期行为**：报告生成≤60秒，支持4种标准模板自动编排

### 4.3 智能体交互模式

碳足迹智能体提供两种交互模式：

| 模式 | 场景 | 特点 |
| --- | --- | --- |
| **对话式引导**（主模式） | 新建任务或需要AI逐步引导 | 左侧AI对话框+右侧任务列表/状态面板，AI主动推送建议和异常卡片 |
| **工作台沉浸式** | 已有任务深度操作 | 左侧九阶段导航+中间AI对话/总览/排放源/溯源树/异常面板+右侧实时状态 |

> 两种模式可随时切换，状态自动保持(keepAlive)。

## 五、关键业务规则

### 5.1 核算任务生命周期

| 状态 | 含义 | 允许的操作 | 转换条件 |
| --- | --- | --- | --- |
| CREATED | 已创建，待配置 | 编辑任务参数、配置产品模型 | 完成Stage 1-3配置后 → DATA_COLLECTING |
| DATA_COLLECTING | 数据采集中 | 填报/导入数据、匹配因子 | 所有排放源数据与因子已锁定 → CALCULATING |
| CALCULATING | 核算执行中 | 查看进度（AI自动执行） | 计算完成 → GOVERNANCE；计算失败 → FAILED |
| GOVERNANCE | 质量治理中 | 处理校验异常卡片 | 所有异常卡片已处理 → COMPLETED |
| COMPLETED | 已完成 | 查看报告、导出、签发 | — |
| FAILED | 失败 | 查看错误日志、回退修正 | 修正后重新提交 → DATA_COLLECTING |

### 5.2 排放因子选用规则

1. **优先本土因子**：有中国本土因子时优先选用，无本土因子时降级使用IPCC/Ecoinvent国际因子（标注地理代表性偏差）
2. **版本时效性**：因子基准年距核算年不超过5年（D-F-04规则），超过6年触发🟠确认卡片
3. **技术匹配度**：因子技术类型与当前工序匹配度评分≤3时直接选用，>3时弹出🟠确认卡片（D-F-05）
4. **复用与引用**：同一因子在多处引用时自动标注crossReference，避免重复计算

### 5.3 数据采集来源优先级

| 优先级 | 来源类型 | DQR可靠性维度评分 | 说明 |
| --- | --- | --- | --- |
| 1（最优） | IoT智能仪表自动采集 | 1分 | 校准仪表连续实测，覆盖完整周期 |
| 2 | ERP/MES系统同步 | 2分 | 合规发票/企业统计报表 |
| 3 | 供应商LCA报告引用 | 2~3分 | 第三方审核的LCA报告 |
| 4 | 供应链问卷回收 | 3分 | 专家估算/行业经验 |
| 5（最低） | 手工填报+估算 | 4~5分 | 粗略估算/无依据 |

### 5.4 七级溯源体系

碳足迹核算结果必须支持从总排放量逐级追溯至因子元数据的七级溯源链：

| 级别 | 名称 | 内容 | 用户价值 |
| --- | --- | --- | --- |
| L1 | 报告级 | 核算报告总览（总量、范围分解、质量评分） | 决策层一览 |
| L2 | 范围级 | Scope 1/2/3分解 | 合规披露 |
| L3 | 工序/环节级 | 生命周期阶段/工艺环节 | 工程师定位 |
| L4 | 排放源级 | 具体排放源（计算公式：value × factor） | 数据核对 |
| L5 | 活动数据级 | 原始采集值、仪表ID、采集方式、采集人 | 数据溯源 |
| L6 | 排放因子级 | 因子值、版本、发布方、有效日期 | 因子审核 |
| L7 | 因子元数据级 | 方法论、数据库引用、文献出处、置信等级 | 方法论核证 |

│  └──────────────────┘   └──────────────────────────┘ │

| 交互方 | 交互类型 | 交互内容 | 说明 |
| --- | --- | --- | --- |
| 组织碳核算智能体 → 本智能体 | 数据共享 | 组织级工厂能耗总量数据（电力/天然气年度消耗） | 产品碳足迹核算的Scope 2活动数据可引用组织级能耗总量，按产量比例分配到单件产品 |
| 本智能体 → 组织碳核算智能体 | 数据共享 | 产品碳足迹核算结果（总量+范围分解） | 组织碳核算的Scope 3下游排放可引用产品碳足迹数据 |
| 双方共享 | 共同维护 | 排放因子库、电网区域因子、用户/组织数据 | 同一因子库，避免重复建设和版本不一致 |
| 双方共享 | 共同使用 | AI对话引擎、权限控制、操作审计 | 共享技术基础设施，降低开发成本 |

> **远期规划**：能碳报告智能体、能碳诊断智能体、能源优化调度智能体属于远期规划，暂不在本期需求范围内。本期报告生成和异常诊断功能内嵌在碳核算智能体中。

## 八、业务约束与假设

### 8.1 业务约束

1. **核算标准强制合规**：输出的报告必须严格符合选定标准(ISO/PAS/GB/EPD)的格式和数据质量要求，不可简化或省略
2. **数据不可篡改**：已提交/已校验的活动数据和排放因子不可直接修改，必须通过"回退→修正→重新校验"流程
3. **负排放声明要求**：回收抵扣/循环信用等负排放项必须在报告中单独标注"含循环信用"，并与"无循环信用"结果并列展示（ISO 14044 §4.3.4.2方法学敏感项）
4. **截断规则限制**：单排放源占比<1%可截断，但累计截断不可超过总排放的5%

### 8.2 业务假设

1. 核算周期内产品工艺路线未发生重大变更（如更换电池类型）
2. 供应商数据响应率≥80%（P2目标，初期可能不足）
3. IoT/ERP系统可提供API接口用于自动数据拉取
4. 排放因子库按年度更新（生态环境部通常次年2月底发布）
5. 第三方核查机构认可本系统的校验记录作为核查依据

## 十、术语表

| 术语 | 定义 |
| --- | --- |
| PCF | Product Carbon Footprint，产品碳足迹 |
| LCA | Life Cycle Assessment，生命周期评价 |
| LCI | Life Cycle Inventory，生命周期清单 |
| LCIA | Life Cycle Impact Assessment，生命周期影响评价 |
| DQR | Data Quality Rating，数据质量评分 |
| Pedigree Matrix | 数据质量五维度评分矩阵（可靠性/完整性/时间/地理/技术） |
| PCR | Product Category Rule，产品类别规则 |

| 排放因子 | 将活动数据转换为温室气体排放量的系数 |
| 活动数据 | 产品生命周期中输入/输出的量化数据（如电力消耗量、运输距离） |

| 范围2(Scope 2) | 外购电力/蒸汽/热力产生的间接排放 |
| 范围3(Scope 3) | 其他间接排放（上游原材料、下游使用废弃、运输） |
| GWP | Global Warming Potential，全球变暖潜值 |
| CBAM | Carbon Border Adjustment Mechanism，碳边境调节机制 |
